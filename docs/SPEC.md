# Argus — v1 Technical Specification

*Status: authoritative build target. Derived from `docs/DECISIONS.md` (binding) and
`docs/research/telemetry-surfaces.md` (verified facts). Where the research doc marks a fact ⚠
unverified, this spec keeps it off the critical path — those places are called out inline as
**[unverified-safe]**.*

Versions in this document were checked against the Go module proxy / npm registry on
2026-08-11, not from memory.

---

## 0. System summary

One Go binary (`argusd`) + Postgres + one Vue SPA (embedded in the binary).

```
Claude Code
  ├─ OTLP/HTTP  (OTEL_EXPORTER_OTLP_ENDPOINT → argusd)  → POST /v1/logs, /v1/metrics
  └─ hooks      ("type": "http")                        → POST /ingest/hook
                                    │
                          ┌─────────▼─────────┐
                          │ internal/ingest   │  decode → normalize → bounded queue
                          └─────────┬─────────┘
                                    │ batches
                    ┌───────────────┼───────────────┐
                    ▼                               ▼
           internal/store (pgx)             internal/stream (SSE hub, in-process)
             Postgres 18                             │
             events (partitioned)          GET /api/v1/stream (firehose)
             + projections + rollups       GET /api/v1/sessions/{id}/stream
                    │
                    ▼
           internal/query → internal/httpapi (chi) → /api/v1/... → Vue SPA
```

Design rule that governs everything below: **the event table is an append-only normalized log;
every other table is a projection derived from it.** A projection can always be rebuilt by
replaying events. This is what makes cross-source merging (OTel vs hooks) tractable — see §1.6.

## 1. Canonical event model

### 1.1 Hierarchy

```
Session          (vendor session.id — one CLI session)
 └─ Turn         (vendor prompt.id — one user prompt and everything it caused)
     └─ Event    (one observed moment; the atom of the system)
```

Plus two projections that are *not* levels of the hierarchy but first-class objects (they are
the differentiator per DECISIONS.md §Thesis):

```
ToolCall         (session.id + tool_use_id) — decision + provenance + outcome + timing
Subagent         (session.id + agent_id) — parent_agent_id edges → tree
```

A Turn may be absent: many events (session lifecycle, MCP connections, config changes) carry no
`prompt.id`. `events.prompt_id` is nullable. Never synthesize a turn to host an event.

### 1.2 Identity and ordering

| Concern | Decision |
|---|---|
| Session identity | `sessions.id text PK` = vendor `session.id` verbatim. Vendors emit UUIDs; cross-vendor collision risk is accepted (and `vendor` is stored alongside for display, not for keying). No surrogate key — it would buy nothing and cost a lookup on every event write. |
| Turn identity | `turns(session_id, prompt_id)` composite PK. `prompt_id` is vendor-supplied. |
| Event identity | `events.id uuid DEFAULT uuidv7()` (Postgres 18 built-in) + `events.seq bigint GENERATED BY DEFAULT AS IDENTITY`. `seq` is the **global monotonic ingest order** and is the SSE `Last-Event-ID` and the keyset-pagination cursor. `uuidv7` id exists so a client can reference an event stably. |
| Timeline ordering | `ORDER BY ts, vendor_seq NULLS LAST, seq`. `vendor_seq` = OTel `event.sequence` (per-session monotonic, verified present on all `claude_code.*` log events). It resolves ties that `ts` at millisecond resolution cannot. |
| Clock | `ts` = event time as reported by the agent (`event.timestamp`, or hook receive time when the payload carries no timestamp). `ingested_at` = server clock. Agent clocks are not trusted for retention or partition placement beyond a sanity clamp: `ts` outside `[now-30d, now+1h]` is clamped to `ingested_at` and the event is flagged `clock_skewed = true`. |

### 1.3 Normalized columns vs raw jsonb

Rule: **a field is promoted to a column only if a v1 query filters, sorts, or aggregates on it.**
Everything else lives in `attrs jsonb` (the full flattened source payload, always, including the
fields that were promoted — promotion is a copy, not a move, so a projection rebuild never needs
a schema migration).

Promoted event columns:

| Column | Type | Why promoted |
|---|---|---|
| `seq` | `bigint` identity | ordering, SSE resume, cursors |
| `id` | `uuid` | stable external reference |
| `ts`, `ingested_at` | `timestamptz` | partition key, timeline, lag metrics |
| `session_id` | `text` | every query |
| `prompt_id` | `text` null | turn grouping |
| `vendor` | `text` | agent-agnostic core (`claude_code`, `codex`, `gemini_cli`, `unknown`) |
| `source` | `text` | `otel_log` \| `otel_metric` \| `hook` \| `sim` — provenance & precedence |
| `kind` | `text` | the normalized taxonomy (§1.4) |
| `event_name` | `text` | vendor raw name (`claude_code.tool_result`, `PostToolUse`) — never lossy |
| `vendor_seq` | `bigint` null | ordering tiebreak |
| `tool_name` | `text` null | tool analytics |
| `tool_use_id` | `text` null | the tool-call join key |
| `decision` | `text` null | `accept` \| `reject` \| `pending` |
| `decision_source` | `text` null | `config`\|`hook`\|`user_permanent`\|`user_temporary`\|`user_abort`\|`user_reject`\|`unknown` — **the differentiator column** |
| `tool_source` | `text` null | `builtin`\|`mcp`\|`sdk_host_builtin_mcp` |
| `model` | `text` null | cost/token analytics |
| `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens` | `bigint` null | analytics |
| `cost_usd` | `numeric(16,8)` null | analytics |
| `cost_source` | `text` null | `reported` \| `estimated` (DECISIONS.md §Cost) |
| `duration_ms` | `integer` null | latency analytics |
| `success` | `boolean` null | error rates |
| `error_type` | `text` null | error breakdown |
| `agent_id`, `parent_agent_id`, `agent_type` | `text` null | subagent tree |
| `permission_mode` | `text` null | mode timeline |
| `file_path` | `text` null | file-touch view (best-effort; only present with `OTEL_LOG_TOOL_DETAILS=1` or from `FileChanged` hooks) |
| `request_id`, `message_uuid` | `text` null | join to vendor API logs / transcripts (v2 enrichment) |
| `clock_skewed` | `boolean` | data-quality flag |
| `attrs` | `jsonb` | everything, verbatim |
| `dedup_key` | `text` | idempotency (§1.7) |

Deliberately **not** promoted: `organization.id`, `user.*`, `terminal.type`, `app.version`,
`app.entrypoint`, `workspace.host_paths`, `workflow.*`, `speed`, `effort`, `query_source`,
`attempt`, `mcp_server_scope`, `tool_input*_size_bytes`, prompt/response content. They are in
`attrs`, queryable via `attrs->>'...'`, and promotable later with a migration + projection
rebuild if a v2 view needs them. Notable judgement call: `query_source ∈ main|subagent|auxiliary`
is *not* promoted because subagent attribution in v1 comes from `agent_id`, which is stronger.

### 1.5 Mapping tables

#### 1.5.1 Claude Code OTel log events → Argus

All 15 documented `claude_code.*` log events. Common attributes applied to every row:
`session.id → session_id`, `prompt.id → prompt_id`, `event.timestamp → ts`,
`event.sequence → vendor_seq`, `event.name → event_name`, `vendor = claude_code`,
`source = otel_log`, everything else → `attrs`.

| `event.name` | kind | Field mapping (attr → column) |

- Cost is **only** on `api_request`. Do not derive per-event cost anywhere else.

| anything else | `unknown` | common fields only |

**Hook payload field names beyond the verified common set are [unverified-safe].** The normalizer
reads them defensively: a missing field yields `NULL`, never an error, never a rejected request.
Every hook body is preserved in `attrs` in full, so a mapping correction is a projection rebuild,
not a data loss.

Recommended hook config shipped in the README (one entry per event, one URL):

```json
{ "hooks": { "PostToolUse": [ { "hooks": [
  { "type": "http", "url": "http://localhost:8080/ingest/hook", "timeout": 5 } ] } ] } }
```

`SessionEnd` has a **1.5 s shared budget across all hooks** (verified). This is a hard constraint
on the ingest endpoint: it must ACK before doing any database work (§3.5).

#### 1.5.3 Precedence when both surfaces describe one moment

The events table stores **both** rows. Merging happens in two places only:

**(a) Projection field precedence** — when OTel and hook rows disagree on a projection field:

| Projection field | Winner | Reason |
|---|---|---|
| `sessions.started_at` / `ended_at` | earliest / latest observed, from any source | monotonic facts |
| `sessions.start_type`, `end_reason` | hook | OTel has `start_type` only as a metric attribute |
| `sessions.cwd`, `project` | hook (`SessionStart.cwd`, `CwdChanged`) | OTel `workspace.host_paths` is a list and less direct |
| `sessions.app_version`, `entrypoint`, `terminal_type`, `user_*`, `org_id` | otel_log | hooks don't carry them |
| `tool_calls.decision`, `decision_source`, `tool_source` | `otel_log`/`tool_decision` > `otel_log`/`tool_result` > `hook` | only `tool_decision` carries the authoritative 6-valued `source` |
| `tool_calls.duration_ms`, sizes | otel_log (`tool_result`) | measured by the agent |
| `tool_calls.started_at` | earliest of `tool.pre` / `tool.decision` | hook `PreToolUse` fires first |
| `tool_calls.success`, `error_type` | otel_log > hook | richer `error_type` vocabulary |
| `turns.*` cost/tokens | always aggregated from `llm.request` events only | never from hooks |
| `subagents.*` | hook (`SubagentStart/Stop` are the only source) | OTel emits no subagent lifecycle event |

Implemented as `COALESCE`-with-rank in the upsert: each projection column has a stored
`*_source_rank smallint`; a write only overwrites when its rank is ≥ the stored rank (equal rank
⇒ later `ts` wins). Ranks: `otel_log=30`, `hook=20`, `otel_metric=10`, `sim`=source it imitates.

**(b) UI timeline collapse** — the timeline endpoint returns raw events; the frontend collapses a
group into one row when all of: same `kind`, same correlation key (`tool_use_id`, else
`prompt_id`, else `session_id`), and `|Δts| ≤ 2000 ms`. The collapsed row shows the union of
fields with the precedence above, and exposes "2 sources" affordance listing the raw events.
Collapsing is **display-only and reversible** (`?collapse=false`). This is deliberately not done
server-side: the rule is heuristic and users debugging their own pipeline need the raw stream.

### 1.6 Projections

| Table | Key | Built from |
|---|---|---|
| `sessions` | `id` | `session.*` events + first/last event seen + aggregates of `llm.request` |
| `turns` | `(session_id, prompt_id)` | `turn.*` + aggregates of events carrying that `prompt_id` |
| `tool_calls` | `id uuid`, unique `(session_id, tool_use_id)` when non-null | `tool.pre`/`tool.decision`/`tool.permission_request`/`tool.result` |
| `subagents` | `(session_id, agent_id)` | `subagent.*`, plus `tool.result` rows where `agent_type` is set (the spawning `Task`/`Agent` call) |

Projections are updated **synchronously in the same transaction as the event insert batch**. This
is a deliberate choice over an async projector: it removes a whole class of "UI is behind" bugs,
and at this scale (a personal/team tool: order 10²–10⁴ events/min worst case) the extra upsert
cost is irrelevant. A full-rebuild path exists for schema/mapping changes:
`argusd rebuild-projections [--from ts]` replays events in `seq` order.

**Tool-call correlation** (`tool_calls.correlation`):

| Value | When |
|---|---|
| `exact` | joined on a non-null `tool_use_id` present in ≥1 OTel and ≥1 hook event |
| `otel_only` | `tool_use_id` present, only OTel events |
| `hook_only` | no `tool_use_id` anywhere for this call |
| `heuristic` | hook event without `tool_use_id` attached to an OTel call by fallback match: same `session_id` + same `prompt_id` + same `tool_name` + nearest open call within 60 s, one-to-one |

The heuristic is confined to this one function (`ingest/normalize.correlateToolCall`) and the
value is surfaced in the API and UI. Because hook `tool_use_id` presence is [unverified], the UI
must remain correct when *every* row is `otel_only` + `hook_only` — i.e. decision provenance
comes from OTel and never depends on the heuristic. **No v1 feature is load-bearing on
`heuristic` correlation.**

### 1.7 Out-of-order arrival, unknown parents, idempotency

Three rules, no exceptions.

1. **Stub-on-reference.** Any event insert first performs
   `INSERT INTO sessions (id, vendor, first_seen_at, ...) VALUES (...) ON CONFLICT (id) DO UPDATE
   SET last_event_at = GREATEST(...)`, and the same for `turns` when `prompt_id` is present. A
   session row can therefore exist with `started_at IS NULL` and `status='unknown'`. The API and
   UI render these normally (labelled *partial*). A later `session.start` fills the gaps via the
   rank rule. Nothing waits, nothing is buffered, nothing is rejected for a missing parent.
2. **Idempotent event insert.** `dedup_key` is unique per partition:
   - `otel_log`: `otel:{session_id}:{vendor_seq}:{event_name}` (`event.sequence` is per-session
     monotonic — verified). If `vendor_seq` is absent: fall through to the hash form.
   - `otel_metric`: `metric:{sha256(name|ts|attrs_canonical)}`
   - `hook`: `hook:{sha256(hook_event_name|session_id|prompt_id|canonical_json(body))}` truncated
     to 32 bytes hex. A hook retried by the agent (or a duplicate config in two settings scopes —
     a real and likely misconfiguration) collapses to one row.
   - Insert uses `ON CONFLICT (ts, dedup_key) DO NOTHING` and counts suppressions
     (`argus_ingest_deduped_total`).
3. **Late data is accepted, rollups self-heal.** Rollups are recomputed for any bucket touched
   since the last watermark, not appended (§2.4), so an event arriving 20 minutes late still
   lands in the right hour. Events arriving after their partition was dropped by retention are
   rejected with a counter (`argus_ingest_too_old_total`).

Status derivation (no explicit event needed): `sessions.status` = `active` if
`last_event_at > now() - ARGUS_SESSION_IDLE_TIMEOUT` (default 15 min) and no `session.end`;
`ended` if a `session.end` exists; `abandoned` otherwise. Computed in SQL, not stored as truth —
so a crashed CLI (no `SessionEnd` hook, which is likely given the 1.5 s budget) does not leave a
forever-"active" session.

### 1.8 OTel metrics vs log events

**Decision: log events are the per-event source of truth for cost, tokens, and everything
attributable to a turn. Metrics are stored raw and feed only (a) rollup series that log events
cannot produce, and (b) a degraded mode when the logs exporter is off.**

Justification (one paragraph): the two surfaces overlap on cost and tokens but the metric form is
strictly weaker for Argus's purpose — `claude_code.cost.usage` and `token.usage` are batched at a
60 s default interval, carry no `prompt.id` and no `tool_use_id`, are subject to
`OTEL_METRICS_INCLUDE_SESSION_ID=false` (so may not even be attributable to a session), and are
temporality-dependent (delta vs cumulative), whereas `claude_code.api_request` log events carry
`cost_usd_micros`, all four token types, `model`, `duration_ms`, `request_id`, `session.id` *and*
`prompt.id` per call at a 5 s export interval. Summing both would double-count, and choosing
metrics would destroy turn-level attribution — the core of the product. Conversely, three metric
series have **no log-event equivalent at all** (`lines_of_code.count`, `active_time.total`,
`commit.count`/`pull_request.count`) and one is a cheap cross-check (`code_edit_tool.decision`),
so metrics are not discardable either.

Concretely:

| Metric | Stored in `metric_samples` | Feeds rollups | Mirrored as an `event` |
|---|---|---|---|
| `claude_code.cost.usage` | yes | **no** (would double-count) — only into `rollup_*` rows with `source='metric'`, a separate row from `source='event'`, never summed together | no |
| `claude_code.token.usage` | yes | same as above | no |
| `claude_code.lines_of_code.count` | yes | **yes** → `loc_added` / `loc_removed` | no |
| `claude_code.active_time.total` | yes | yes → `active_seconds` | no |
| `claude_code.commit.count`, `pull_request.count` | yes | yes → `commits`, `pull_requests` | no |
| `claude_code.session.count` | yes | no (sessions counted from the `sessions` table) | no |
| `claude_code.code_edit_tool.decision` | yes | yes → `edit_decisions_{accept,reject}` (cross-check panel only) | no |
| unknown metric name | yes | no | no |

Rollup rows carry `source ∈ ('event','metric')` in their primary key. The analytics API defaults
to `source=event` and exposes `source=metric` explicitly; the UI never adds them. A "logs
exporter appears to be off" banner is shown when a project has `metric` rows and zero `event`
cost rows in the window — this converts the most likely user misconfiguration into a visible hint
rather than a silently empty dashboard.

**Temporality.** README instructs `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE=delta`.
Cumulative is still handled: `metric_series_state(series_hash, last_ts, last_value)` lets the
rollup job diff consecutive cumulative points; a negative diff is treated as a counter reset and
the raw value is taken. Gauges are last-value-wins per bucket.

## 2. Postgres schema

Target **Postgres 18** (pinned in compose). Uses `uuidv7()` (18+). No extensions required.
Migrations are plain SQL, embedded (§3.6). All timestamps `timestamptz`, all money
`numeric(16,8)`.

### 2.1 Core tables

```sql
-- 001_core.sql

CREATE TABLE sessions (
    id                    text PRIMARY KEY,
    vendor                text NOT NULL DEFAULT 'unknown',
    project               text,                  -- basename(cwd), the analytics dimension
    cwd                   text,
    start_type            text,                  -- fresh|resume|continue|agents_view
    end_reason            text,
    permission_mode       text,
    app_version           text,
    entrypoint            text,
    terminal_type         text,
    user_email            text,
    user_account_uuid     text,
    organization_id       text,
    started_at            timestamptz,           -- NULL until session.start seen
    ended_at              timestamptz,
    first_seen_at         timestamptz NOT NULL,
    last_event_at         timestamptz NOT NULL,
```

No FK from `events` to `sessions`: partition-wide FK enforcement costs write throughput and the

**Partitioning: monthly RANGE on `ts`.** Monthly (not daily) because 90 days of a personal/team
tool is ~4 partitions — daily would mean 90 planning-time partitions for a marginal pruning win.
Retention granularity is therefore coarse (a partition is dropped only when *entirely* older than
the cutoff), which is documented and acceptable; a `--precise` retention mode additionally
`DELETE`s in batches within the boundary partition.

Indexes (each justified):


Not created: a GIN index on `attrs`. `attrs` queries in v1 are all inside a single session
(already narrowed by the session index) or ad-hoc SQL. Adding GIN would roughly double write
amplification for no v1 query. Revisit if a v2 "search all sessions by tool parameter" ships.

### 2.4 Rollups, prices, jobs

```sql
-- 004_rollups.sql

CREATE TABLE rollup_hourly (

CREATE TABLE model_prices (
    model              text NOT NULL,
    effective_from     date NOT NULL,
    currency           text NOT NULL DEFAULT 'USD',
    input_per_mtok     numeric(12,6) NOT NULL,
    output_per_mtok    numeric(12,6) NOT NULL,
    cache_read_per_mtok    numeric(12,6) NOT NULL DEFAULT 0,
    cache_write_per_mtok   numeric(12,6) NOT NULL DEFAULT 0,
    source             text NOT NULL DEFAULT 'repo',    -- repo|user
    PRIMARY KEY (model, effective_from)
);
-- lookup: latest effective_from <= event date, exact model, else longest matching prefix
CREATE INDEX ON model_prices (model text_pattern_ops, effective_from DESC);

CREATE TABLE job_state (
    job          text PRIMARY KEY,   -- 'rollup_hourly' | 'retention' | 'partitions'
    watermark    bigint,             -- max events.seq processed
    watermark_ts timestamptz,
    last_run_at  timestamptz,
    last_error   text
);
```

**Rollup job.** Runs every `ARGUS_ROLLUP_INTERVAL` (default 60 s), single-flight, advisory-locked
(`pg_try_advisory_lock`) so two `argusd` replicas don't duplicate work.

1. Read `job_state.watermark` for `rollup_hourly`.
2. `SELECT DISTINCT date_trunc('hour', ts) FROM events WHERE seq > :w` → the dirty bucket set,
   capped at `ARGUS_ROLLUP_MAX_BUCKETS` (default 200) per run to bound a backfill.
3. For each dirty bucket: `INSERT … SELECT … ON CONFLICT (pk) DO UPDATE SET <all metrics> = EXCLUDED.*`
   — a **full recompute of that bucket**, not an increment. Idempotent, late-data-safe, and the
   only correct choice given out-of-order arrival.
4. Same pass for metric-sourced rows from `metric_samples` (with the cumulative-diff step).
5. Advance the watermark to `max(seq)` seen in step 2, in the same transaction.
6. `rollup_daily` recomputed from `rollup_hourly` for the affected days.

Cost in rollups: `cost_reported_usd` = `SUM(cost_usd) WHERE cost_source='reported'`;
`cost_estimated_usd` = for `llm.request` rows with `cost_usd IS NULL`, tokens × `model_prices`
resolved at event date. The two are **never summed into one column** at the storage layer; the API
exposes `cost_usd = reported + estimated` plus `estimated_share` so the UI can flag it.

**Partition manager job.** Hourly. Ensures partitions exist for the current month and the next
two (`CREATE TABLE IF NOT EXISTS … PARTITION OF … FOR VALUES FROM … TO …` + the index set), plus
a `DEFAULT` partition that must stay empty — a non-empty default partition raises
`argus_partition_default_rows` and a startup warning (it means clock clamping failed).

**Retention job.** Daily at `ARGUS_RETENTION_HOUR` (default 04:00 local). Drops `events` and
`metric_samples` partitions whose upper bound ≤ `now() - ARGUS_RETENTION_RAW_DAYS` (default 90).
Rollups and projections are never deleted, so a 3-year-old session keeps its row and its
aggregates with an empty timeline (the UI says "raw events expired"). Deleting `sessions` older
than `ARGUS_RETENTION_SESSION_DAYS` (default 0 = never) is opt-in and cascades. Dry-run:
`argusd retention --dry-run` prints the partitions it would drop.

### 2.5 Query patterns → index map

| Query (v1 endpoint) | Plan |
|---|---|
| session list, filtered + keyset | `sessions (last_event_at DESC)` index; add `sessions (project, last_event_at DESC)` and `sessions (status, last_event_at DESC)` |
| session timeline | `events (session_id, ts, seq)` — single partition per month touched |
| tool calls of a session | `tool_calls (session_id, started_at)` |
| subagent tree | `subagents (session_id, parent_agent_id)` + recursive CTE |
| analytics timeseries | `rollup_hourly (bucket DESC)` / `(project, bucket DESC)` — never touches `events` |
| decision breakdown | `rollup_hourly` for counts; `tool_calls (decision, decision_source, started_at DESC)` for the drill-down list |
| live firehose backfill | `events (ingested_at)` bounded to the last 5 min |

Every analytics read hits a rollup. **No v1 endpoint aggregates over `events` at request time**;
that invariant is asserted by an integration test that runs `EXPLAIN` on each analytics query and
fails if `events` appears in the plan.

### 3.3 The storage seam

`internal/store/store.go` — narrow, intention-revealing, no `*sql.Rows` or pgx types leak:

```go
package store

type Store interface {
    Writer
    Reader
    Maintenance
    Health(ctx context.Context) error
    Close()
}

// Writer is what ingest needs. One method: batches are the unit of work.
type Writer interface {
    // WriteBatch inserts events idempotently and updates all projections in ONE transaction.
    // Returns per-event outcomes so ingest can count dedup suppressions and fan out to stream
    // only the events that were actually persisted.
    WriteBatch(ctx context.Context, b []model.Event) (BatchResult, error)
}

type Reader interface {
    ListSessions(ctx context.Context, f SessionFilter, p Page) ([]model.SessionSummary, Cursor, error)
    GetSession(ctx context.Context, id string) (*model.SessionDetail, error)
    ListTurns(ctx context.Context, sessionID string) ([]model.Turn, error)
    ListEvents(ctx context.Context, f EventFilter, p Page) ([]model.Event, Cursor, error)
    ListToolCalls(ctx context.Context, f ToolCallFilter, p Page) ([]model.ToolCall, Cursor, error)
    SubagentTree(ctx context.Context, sessionID string) ([]model.SubagentNode, error)
    AnalyticsSummary(ctx context.Context, f AnalyticsFilter) (model.Summary, error)
    AnalyticsSeries(ctx context.Context, f AnalyticsFilter, g Grouping) (model.Series, error)
    AnalyticsBreakdown(ctx context.Context, f AnalyticsFilter, d Dimension) (model.Breakdown, error)
    EventsSince(ctx context.Context, seq int64, limit int) ([]model.Event, error) // SSE replay
    Facets(ctx context.Context) (model.Facets, error)                            // projects, models, tools
}
```

Implementations: `postgres.Store` (production) and `storetest.Fake` (in-memory, used by httpapi
and stream unit tests — not by store tests). ClickHouse in v2 implements `Writer`+`Reader`;
`Maintenance` is allowed to be backend-specific and is reached through a type assertion in the
job scheduler, not through the common interface. Query construction: sqlc for everything fixed;
the two dynamic-filter queries (`ListSessions`, `ListEvents`) are hand-built with a tiny
whitelist-based clause builder in `postgres/filter.go` — no string interpolation of user input,
placeholders only, and a unit test that feeds every filter permutation.

### 3.4 OTLP/HTTP receiver

Routes, mounted at the root so `OTEL_EXPORTER_OTLP_ENDPOINT=http://argus:8080` works with zero
extra config (the OTel SDK appends `/v1/logs` itself):

| Route | Behaviour |
|---|---|
| `POST /v1/logs` | ingest |
| `POST /v1/metrics` | ingest |
| `POST /v1/traces` | accept, discard, count `argus_otlp_traces_discarded_total`, return an empty `ExportTraceServiceResponse`. Traces are out of scope (DECISIONS.md) but silently 404-ing an exporter causes noisy client-side error loops; accepting and dropping is friendlier and is documented. |

Content negotiation: `Content-Type: application/x-protobuf` → `proto.Unmarshal`;
`application/json` → `protojson.Unmarshal` with `DiscardUnknown: true` (mandatory: Claude Code
may add fields). Any other type → 415. `Content-Encoding: gzip` supported, decompressed with a
`ARGUS_INGEST_MAX_BODY_BYTES` (default 8 MiB) limit on the *decompressed* stream to prevent zip
bombs. Body size limit enforced with `http.MaxBytesReader` before decode.

Responses follow the OTLP/HTTP spec:
- full success → `200` + empty `Export*ServiceResponse`;
- some records unmappable → `200` + `partial_success{rejected_log_records: N, error_message}`
  (they were still *stored*, as `kind='unknown'`; "rejected" is reserved for records we could not
  attribute to a session at all);
- queue full → `503` + `Retry-After: 1`, empty body. The OTel SDK retries with backoff, which is
  exactly the desired backpressure behaviour.
- malformed protobuf → `400` with an `application/x-protobuf` `Status`.

Decode path detail: walk `ResourceLogs → ScopeLogs → LogRecord`. Session/resource attributes are
merged with record attributes (record wins). `LogRecord.TimeUnixNano` is preferred over the
`event.timestamp` string attribute when both exist (fewer parse failures); disagreement > 5 s
raises `clock_skewed`. `LogRecord.EventName` (OTLP 1.x field) is checked before the `event.name`
attribute.

### 3.5 Hooks webhook

`POST /ingest/hook`, `Content-Type: application/json`, one hook payload per request (Claude Code
sends one). Also accepts a JSON array for batch replay by `argus-sim`.

**The 1.5 s `SessionEnd` budget dictates the design**: the handler validates
`session_id` presence, computes the dedup key, enqueues, and returns `202 Accepted` with
`{"ok":true}`. It never touches the database. Target p99 < 20 ms; a Prometheus histogram
`argus_hook_handler_duration_seconds` guards it and a test asserts the handler makes zero store
calls. Queue full → `429` + `Retry-After: 1` (hooks are not retried by Claude Code, so this is a
counted data loss: `argus_ingest_dropped_total{source="hook"}` — surfaced in the UI's health
strip, because silent loss in an observability tool is unacceptable).

Optional shared-secret: if `ARGUS_INGEST_TOKEN` is set, both OTLP and hook endpoints require
`Authorization: Bearer <token>` (constant-time compare). Unset by default (DECISIONS.md: no auth
in v1) — this is the auth-shaped seam, implemented as `httpapi/middleware.RequireIngestToken`
sitting where a real authenticator will later go. The read API has the same seam
(`ARGUS_API_TOKEN`), also unset by default.

Hooks must never block the agent: the response is always sent, `hook_event_name` is echoed, and
the body never contains a hook *decision* field (Argus is observe-only; blocking/intervening is
explicitly a non-goal).

### 3.6 Pipeline: batching and backpressure

```
handler → normalize (in the request goroutine; cheap, pure, testable)
        → queue: chan []model.Event  (cap ARGUS_INGEST_QUEUE=1024 batches)
        → N workers (ARGUS_INGEST_WORKERS=4)
             accumulate until ARGUS_INGEST_BATCH_SIZE=500 events or ARGUS_INGEST_FLUSH=250ms
             → store.WriteBatch (one tx)
             → stream.Hub.Publish(persisted events)
```

- Normalization happens **before** enqueue so a malformed payload fails fast with a 400 and never
  occupies queue capacity.
- Non-blocking enqueue (`select` with `default`) — the queue is a shock absorber, not a buffer to
  hide a slow database in. Full queue = load shed with a correct HTTP status, always.
- `WriteBatch` failure → retry the batch up to 3× with jittered backoff (100 ms, 400 ms, 1.6 s);
  then drop with `argus_ingest_write_failed_total` and an ERROR log including the first event's
  session id. Deliberately no disk spool in v1: it is a second storage system with its own
  failure modes, and Postgres being down for > 5 s is a visible operational failure, not
  something to paper over. (v2 backlog if it hurts in practice.)
- Ordering: `seq` is assigned by Postgres, so parallel workers can interleave. This is fine —
  `seq` orders *ingest*, timeline order is `(ts, vendor_seq, seq)`. Documented so nobody "fixes"
  it into a single writer.
- Self-metrics: queue depth gauge, batch-size histogram, per-source event counters, dedup counter,
  write-duration histogram, `argus_ingest_lag_seconds` (`ingested_at - ts`, p50/p99).

### 3.8 Subcommands and lifecycle

`argusd <serve|migrate|sim|retention|rebuild-projections|config|version>`. Flat `flag` package
per subcommand — no cobra. `argus-sim` is a symlink-style alias: `argusd sim` is canonical, and a
tiny `cmd/argus-sim` shim exists because DECISIONS.md names the binary (it calls the same
`internal/sim`).

- `migrate` — `up` (default), `status`, `down-to N`. Goose over `embed.FS`; also invoked
  automatically by `serve` when `ARGUS_AUTO_MIGRATE=true`, guarded by a Postgres advisory lock so
  concurrent starts are safe.
- `serve` — starts HTTP, pipeline, stream hub, and the three jobs (partitions, rollups,
  retention) in an `errgroup`-shaped supervisor.
- Graceful shutdown on SIGINT/SIGTERM: (1) `/readyz` starts failing; (2) `http.Server.Shutdown`
  with `ARGUS_SHUTDOWN_GRACE` (default 15 s) — in-flight ingest requests finish, SSE subscribers
  get a final `event: shutdown` and the connection closes; (3) close the ingest queue and drain
  it fully (bounded by the same grace); (4) `pool.Close()`. Exit code 0 only if the drain
  completed; 1 if events were dropped, so a compose restart loop is visible.

Self-observability: `GET /healthz` (liveness, no DB), `GET /readyz` (DB ping + migrations current
+ queue not saturated), `GET /metrics` (Prometheus). Structured logs via slog with `request_id`
(chi middleware) on every line; ingest logs are sampled (1/100 on success) to avoid an
observability tool DoS-ing its own log file.

## 4. REST API

`/api/v1`, JSON, OpenAPI 3.1 at `server/api/openapi.yaml` (hand-authored — the spec is the source
of truth and is reviewed like code; generating it from Go annotations makes it an afterthought).

### 4.1 Conventions

- **Envelope**: collections return `{ "data": [...], "page": { "next_cursor": "…"|null, "has_more": bool } }`.
  Single resources return the object bare.
- **Pagination**: keyset only. `?limit=` (default 50, max 500) + `?cursor=`. Cursor = URL-safe
  base64 of `{"k":"<sort key>","v":[…]}`; opaque to clients, validated and rejected with 400 on
  tamper. No offset paging anywhere (session lists get long and offsets lie under concurrent
  ingest).
- **Time params**: `from`, `to` as RFC 3339 or a relative shorthand (`-24h`, `-7d`). Default
  window `-24h` for analytics, unbounded for session list.
- **Errors**: RFC 9457 `application/problem+json` — `{type, title, status, detail, instance,
  errors?}`. `type` is a stable URN (`urn:argus:error:invalid-cursor`).
- **Filter param semantics**: repeated params OR within a field, AND across fields
  (`?project=a&project=b&model=x`).
- **`ETag`/`If-None-Match`** on session detail and analytics responses (hash of the underlying
  `max(seq)` + filter) — makes the UI's polling fallback cheap.

### 4.4 OpenAPI-first and the TS client

- `server/api/openapi.yaml` is written first for every endpoint; a handler PR that changes a shape

  friction, and it fails loudly, which is the point.
- Client side: `pnpm gen:api` runs `openapi-typescript@7.13.0` → `web/src/api/schema.d.ts`, and a

  Generated file is committed; CI regenerates and `git diff --exit-code`s it (drift = red build).
- SSE payload schemas live in the same OpenAPI file as `components.schemas.StreamEvent` (SSE
  itself is documented as a `text/event-stream` response) so the frontend gets types for stream
  frames too.

## 5. SSE design

Two channels, one hub.

| Channel | Route | Contents |
|---|---|---|
| session | `GET /api/v1/sessions/{id}/stream` | events of that session + its projection updates |
| firehose | `GET /api/v1/stream?kinds=&project=&vendor=` | all events (filtered), plus `session.upsert` frames |

### 5.1 Framing

```
id: 918234
event: event
data: {"seq":918234,"ts":"…","session_id":"3f7a…","kind":"tool.result", …}

id: 918234
event: session
data: {"id":"3f7a…","status":"active","turn_count":12,"cost":{…}}

event: stats
data: {"events_per_sec":42.1,"active_sessions":3,"queue_depth":0,"ingest_lag_ms":180,"dropped_total":0}

: heartbeat
```

- `event: event` — a persisted event, **slim shape** (no `attrs`; the UI opens a drawer and
  fetches the full event by id when the user clicks). Prevents a 60 KB frame per raw-body event.
- `event: session` — debounced (500 ms per session) projection snapshot, so the live list updates
  counters without the client recomputing aggregates from the event stream.
- `event: stats` — every 2 s, pipeline health. Feeds the live-view header and makes dropped events
  visible.
- `event: lag` — `{"dropped": N}` when a subscriber's buffer overflowed (the client then refetches
  rather than trusting its local state).
- `event: shutdown` — sent on graceful shutdown so the browser reconnects instead of showing an
  error.
- `: heartbeat` comment every `ARGUS_STREAM_HEARTBEAT` (15 s) — keeps proxies from idling the
  connection out.
- `retry: 3000` sent once at stream open.
- `id:` is the event `seq` — only on `event: event` frames (the only replayable kind).

### 5.2 Reconnect / Last-Event-ID

On `Last-Event-ID: <seq>` (or `?from_seq=`), the handler calls `store.EventsSince(seq, limit)`
bounded by `ARGUS_STREAM_REPLAY_WINDOW` (5 min) and `ARGUS_STREAM_REPLAY_MAX` (2000 events),
streams the backlog, then attaches to the live hub. If the requested `seq` is older than the
window, it sends `event: reset` first (`{"reason":"replay_window_exceeded","from_seq":N}`) and the
client drops local state and refetches via REST. Correctness rule: **attach to the hub before
running the DB replay query**, buffering live events meanwhile, then dedupe by `seq` on flush —
otherwise events landing between query and attach are lost.

### 5.3 Hub

```go
type Hub struct { /* mu, map[subID]*sub, topics */ }
func (h *Hub) Subscribe(topic Topic, filter Filter) (*Subscription, error) // buffered chan
func (h *Hub) Publish(evs []model.Event, sess []model.SessionSummary)
```

- In-process, no Redis (single-binary constraint). `Publish` is called by the ingest workers
  **after** the write transaction commits, with only the events that were actually persisted (so
  a dedup-suppressed event never appears twice in a browser).
- Topics: `Topic{Kind: All}` and `Topic{Kind: Session, ID: id}`. A map keyed by session id keeps
  fan-out O(subscribers-of-that-session) instead of O(all subscribers).
- Per-subscriber buffered channel (`ARGUS_STREAM_BUFFER`, 256). Full → drop oldest, increment the
  subscriber's `dropped` counter, and schedule a `lag` frame. **Publish never blocks** — a stalled
  browser must not be able to slow ingestion. This is the single most important property of the
  hub and gets a dedicated test.
- `ARGUS_STREAM_MAX_SUBSCRIBERS` (default 100) → 503 beyond it.
- Writer goroutine per connection: `select` on subscription chan / heartbeat ticker /
  `r.Context().Done()`; `http.NewResponseController(w).Flush()` after each frame (Go 1.20+ API,
  works through chi's wrapped writer). Headers: `Content-Type: text/event-stream`,
  `Cache-Control: no-store`, `X-Accel-Buffering: no`, `Connection: keep-alive`.
- Sim and tests use the same hub, so `argusd sim` visibly drives the live view end to end.

## 7. argus-sim

`argusd sim` / `argus-sim` — a client that speaks the **real wire protocols to a real server**
(`--target http://localhost:8080`). It never touches the database, never imports `store`. That
constraint is what makes it a genuine end-to-end exercise of the ingestion path, and it means
`docker compose up && argus-sim` is the demo.

### 7.1 Generated traffic

A session lifecycle, per virtual session:

1. `SessionStart` hook (`start_type` weighted fresh 0.7 / resume 0.2 / continue 0.1) + OTel
   `claude_code.session.count` metric point.
2. 1–20 turns (geometric, mean 6). Per turn:
   - `UserPromptSubmit` hook **and** `claude_code.user_prompt` log event with the same
     `prompt_id` (this is what exercises cross-source merge).
   - 1–8 `claude_code.api_request` events. Tokens: lognormal — input μ=ln(1500) σ=0.8, output
     μ=ln(600) σ=1.0, `cache_read` 0 or lognormal μ=ln(40000) σ=1.2 (p=0.75), `cache_creation`
     lognormal μ=ln(3000) σ=1.0 (p=0.3). `duration_ms` lognormal μ=ln(4000) σ=0.7.
     `cost_usd_micros` computed from a built-in price table so reported cost is self-consistent;
     `--cost-mode=omit` drops it to exercise the estimated-cost path.
   - 0–12 tool calls. Tool mix: Read 0.28, Edit 0.18, Bash 0.16, Grep 0.10, Write 0.08, Glob 0.06,
     Task 0.05, WebFetch 0.04, `mcp__*` 0.05. Each: `PreToolUse` hook → `claude_code.tool_decision`
     (accept 0.88 / reject 0.12; `source` distribution config 0.55, hook 0.05, user_permanent 0.15,
     user_temporary 0.15, user_reject 0.08, user_abort 0.02) → if accepted, `claude_code.tool_result`
     (+ `PostToolUse` hook, `success` 0.93) with `duration_ms` lognormal per tool family.
     `--tool-use-id-in-hooks=true|false` (default **false**, matching the unverified assumption)
     toggles whether hooks carry `tool_use_id` — this is how the `heuristic` correlation path and
     its absence are both tested.
   - `Task`/`Agent` calls (p=0.05 per tool call, max depth 2) emit `SubagentStart`, a nested
     mini-session of api_requests + tool calls with `agent_id`/`parent_agent_id`, then
     `SubagentStop`.
   - occasional `PermissionRequest` before a `user_*` decision, with a human-latency gap
     (lognormal μ=ln(3000) σ=1.1) so `wait_ms` is realistic.
   - `Stop` hook + `claude_code.assistant_response`.
   - p=0.03 `claude_code.api_error`, p=0.01 `api_refusal`, p=0.02 `permission_mode_changed`,
     p=0.05 `FileChanged` burst, p=0.02 `PreCompact`/`PostCompact` pair.
3. `SessionEnd` hook (p=0.85 — 15 % of sessions are *abandoned* with no end event, because that is
   real, and the `abandoned` status logic must be exercised).
4. Every 60 s of simulated time: an OTLP metrics export carrying `cost.usage`, `token.usage`,
   `lines_of_code.count`, `active_time.total`, `code_edit_tool.decision`, and occasionally
   `commit.count` / `pull_request.count`.

Projects drawn from a fixed set (`argus`, `platform`, `micro-services/studio`, `dotfiles`,
`legacy-app`), models from `claude-opus-5`, `claude-sonnet-4-5`, `claude-haiku-4-5` weighted
0.2/0.65/0.15. `legacy-app` is configured metrics-only (no log events) so the "logs exporter
appears off" banner has a demo case.

Also generated deliberately-nasty traffic behind flags, because these paths need a repro:
`--chaos-duplicates` (resend 3 % of payloads → dedup), `--chaos-out-of-order` (hold 5 % of events
for 5–60 s → late rollups), `--chaos-orphans` (start a session's turn events before its
`SessionStart` → stub-on-reference), `--chaos-clock-skew` (2 % of events ±1 h → clamping),
`--chaos-unknown` (emit an invented `event.name` → `kind='unknown'`).

### 7.2 Wire output, determinism, rate control

- Transport: OTLP/HTTP protobuf by default (`--otlp-protocol=http/protobuf|http/json`) to
  `POST {target}/v1/logs` and `/v1/metrics`, built with the same `go.opentelemetry.io/proto/otlp`
  types the receiver decodes; hooks as `POST {target}/ingest/hook`. Batching mirrors Claude Code's
  defaults (logs 5 s, metrics 60 s) unless `--flush-immediately`.
  `--out=dir/` writes the same payloads to files instead of POSTing (fixture generation for tests —
  the Go and Vue test suites both consume sim-produced fixtures, so fixtures cannot drift from the
  normalizer's expectations).
- Determinism: `--seed=N` (default 1) drives a single `math/rand/v2.PCG`; every random draw comes
  from it, and per-session generators are derived by `rand.NewPCG(seed, sessionOrdinal)` so a
  session's content is independent of concurrency. Identical seed + flags ⇒ byte-identical payload
  sequence (asserted by a golden test over `--out`).
- Modes: `--mode=demo` (default: `--sessions=25 --speed=200 --backfill=14d` — instant populated
  dashboards, with historical timestamps so analytics has shape) and `--mode=load`
  (`--rate=<events/s> --concurrency=N --duration=…`, live timestamps, for backpressure testing).
- `--speed=X` compresses simulated time by X; timestamps are simulated-clock, so a 14-day backfill
  lands in seconds.
- Reports on exit: sessions/events/hooks/metric points sent, HTTP status histogram, throughput,
  and non-2xx bodies — so a 429/503 storm during load testing is legible.

## 8. Deploy & CI

### 8.1 Dockerfile (`server/Dockerfile`, context = repo root)

```
FROM node:25-alpine AS web
  corepack enable; pnpm install --frozen-lockfile; pnpm build   → /web/dist

FROM golang:1.25-alpine AS build
  go mod download (cached layer)
  COPY --from=web /web/dist server/internal/httpapi/assets/dist
  CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X …/internal/telemetry.Version=$VERSION \
      -X …/internal/telemetry.Commit=$COMMIT" ./cmd/argusd

FROM gcr.io/distroless/static-debian12:nonroot
  COPY --from=build /out/argusd /argusd
  USER nonroot:nonroot
  EXPOSE 8080
  ENTRYPOINT ["/argusd", "serve"]
```

Distroless (not alpine): the binary is static, nothing needs a shell, and the smaller attack
surface is free. Trade-off accepted: no `docker exec sh` — debugging uses `/healthz`, `/metrics`,
logs, and a `:debug` tag variant published from `distroless/static:debug` for when a shell is
genuinely needed. Web assets are embedded rather than served by nginx: one container, one port,
no CORS, no reverse-proxy config in the quickstart.

### 8.2 docker-compose (`deploy/docker-compose.yml`)

## 9. Non-goals and open questions

### 9.1 Non-goals in v1 (restated from DECISIONS.md, plus what this spec adds)

From DECISIONS.md: alerting; fleet view; auth (seam only); retention UI; git-join ($/merged-MR);
JSONL transcript enrichment; OTel traces ingestion (accepted-and-discarded at `/v1/traces`);
ClickHouse backend; multi-tenancy; SaaS.

Added by this spec, same reasoning:
- **No OTLP/gRPC receiver.** HTTP only. `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf` is one env var
  and gRPC doubles the receiver surface.
- **No prompt/response content UI.** Content is opt-in in Claude Code and stored in `attrs` if
  sent, viewable in the raw-event drawer, but there is no rendered conversation view — that is a
  transcript feature and belongs with v2 JSONL enrichment.
- **No write path from the UI.** The whole API is read-only apart from ingest. No annotations, no
  tagging, no deletes.
- **No disk spool for ingest** (§3.6), **no GIN index on `attrs`** (§2.2), **no async projector**
  (§1.6), **no server-side timeline collapsing** (§1.5.3) — each rejected with its reason above.
- **No Analytics API / Compliance API polling.** Both are org-scoped and daily-aggregated; they
  belong to a fleet-view epic.
- **No cross-agent adapters beyond the `vendor` field and the `unknown` fallback.** Codex/Gemini
  mappers are additive later precisely because the taxonomy is vendor-neutral; shipping them
  untested against a real agent would be theatre.
