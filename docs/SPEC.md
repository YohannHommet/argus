`docs/research/telemetry-surfaces.md` (research) and
`docs/research/live-capture-2026-08-11.md` (**live capture — takes precedence over the research doc

Dependency versions were checked against the Go module proxy / npm registry on 2026-08-11, not from

**Revision 3 (2026-08-12)** — amended after adversarial review `docs/review/spec-review-1.md` and

## 0. System summary

One Go binary (`argusd`) + Postgres + one Vue SPA (embedded in the binary).

```
Claude Code
  ├─ OTLP/HTTP  (OTEL_EXPORTER_OTLP_ENDPOINT → argusd)  → POST /v1/logs, /v1/metrics
  └─ hooks      ("type": "http")                        → POST /ingest/hook
                                    │
                          ┌─────────▼─────────┐
                          │ internal/ingest   │  decode → normalize → bounded queue
                          └─────────┬─────────┘
                                    │ batches
                    ┌───────────────┼───────────────┐
                    ▼                               ▼
           internal/store (pgx)             internal/stream (SSE hub, in-process)
             Postgres 18                             │
             events (partitioned)          GET /api/v1/stream (firehose)
             + projections + rollups       GET /api/v1/sessions/{id}/stream
                    │
                    ▼
           internal/query → internal/httpapi (chi) → /api/v1/... → Vue SPA
```

Design rule that governs everything below: **the event table is an append-only normalized log;
every other table is a projection derived from it.** A projection can always be rebuilt by
replaying events. This is what makes cross-source merging (OTel vs hooks) tractable — see §1.6.

Second rule, promoted to the top after the live capture: **no vendor attribute vocabulary is ever
constrained.** No `CHECK` constraint, no Postgres enum, and no Go enum that can reject a value, for
`query_source`, `terminal_type`, `decision_source`, `tool_source`, `start_type`, `permission_mode`,
or any other agent-supplied string. The capture found `query_source` values (`sdk`,
`generate_session_title`) and a `terminal.type` (`wsl-Ubuntu`) that the documentation does not list.
Only Argus's *own* taxonomy (`kind`, `source`, `correlation`, `status`) is closed, and even `kind`
has the `unknown` escape hatch.

## 1. Canonical event model

### 1.1 Hierarchy

```
Session          (vendor session.id — one CLI session)
 └─ Turn         (vendor prompt.id — one user prompt and everything it caused)
     └─ Event    (one observed moment; the atom of the system)
```

Plus two projections that are *not* levels of the hierarchy but first-class objects (they are the
differentiator per DECISIONS.md §Thesis):

```
ToolCall         (session.id + tool_use_id) — decision + provenance + outcome + timing
Subagent         (session.id + agent_id) — parent_agent_id edges → tree
```

A Turn may be absent, and this is normal rather than exceptional: session lifecycle events, MCP
connections, `hook_registered`, `plugin_loaded` and out-of-turn auxiliary model calls carry no
`prompt.id`. The capture shows `api_request` with `prompt.id` on 5 of 6 records — the exception being
a `generate_session_title` call that genuinely happens outside any turn. `events.prompt_id` is
nullable and **never synthesized** to host an event; such cost is attributed to the session with
`prompt_id IS NULL` and surfaces in the UI as "out-of-turn".

### 1.2 Identity and ordering

| Concern | Decision |
|---|---|
| Session identity | `sessions.id text PK` = vendor `session.id` verbatim. Vendors emit UUIDs; cross-vendor collision risk is accepted (`vendor` is stored alongside for display, not for keying). No surrogate key — it would buy nothing and cost a lookup on every event write. |
| Turn identity | `turns(session_id, prompt_id)` composite PK. `prompt_id` is vendor-supplied. |
| Event identity | `events.id uuid DEFAULT uuidv7()` (Postgres 18 built-in, verified on 18.4) + `events.seq bigint GENERATED BY DEFAULT AS IDENTITY`. `seq` is the ingest-order tiebreak and, paired with `ts`, the SSE resume position and the keyset cursor. **`seq` alone is never a scan predicate** (§3.3, §5.2) and is never a rollup watermark (§2.4). |
| Event addressing | The PK is `(ts, seq)`, so a single event is addressed by an opaque `event_ref` = base64url of `ts`+`seq`, present on every event payload. There is **no index on `events.id`**; `id` is a stable opaque identifier for logs and support, not a lookup key. |
| Timeline ordering | `ORDER BY ts, vendor_seq NULLS LAST, seq`. `vendor_seq` = OTel `event.sequence`. **Verified by live capture (2026-08-11)**: per-session monotonic, dense, **zero-based**, one counter shared across all event kinds, resetting on a new `session.id` (0–29 across 30 records; 0–35 across 36). It is used as an ordering tiebreak and as a dedup-key component; because the sample was two sessions, the dedup key *also* carries a content hash so a future regression in this counter cannot cause silent event loss (§1.7 rule 2). |
| Clock | `ts` = event time as reported by the agent (`event.timestamp`, or hook receipt time when the payload carries no timestamp). `ingested_at` = server clock. Agent clocks are sanity-clamped: `ts` outside `[now − ARGUS_RETENTION_RAW_DAYS, now + 1h]` is clamped to `ingested_at` and flagged `clock_skewed = true`. The lower bound is tied to retention (not a fixed 30 days) so a legitimate backfill inside the retention window is never rewritten, and so no clamped event can address a dropped partition. |

### 1.3 Normalized columns vs raw jsonb

Rule: **a field is promoted to a column only if a v1 query filters, sorts, or aggregates on it.**
Everything else lives in `attrs jsonb` (the full flattened source payload, always, including the
promoted fields — promotion is a copy, not a move, so a projection rebuild never needs a schema
migration).

Promoted event columns:

| Column | Type | Why promoted |
|---|---|---|
| `seq` | `bigint` identity | ordering tiebreak, cursor component |
| `id` | `uuid` | opaque stable identifier (not indexed) |
| `ts`, `ingested_at` | `timestamptz` | partition key, timeline, lag metrics |
| `session_id` | `text` | every query |
| `prompt_id` | `text` null | turn grouping |
| `vendor` | `text` | agent-agnostic core (`claude_code`, `codex`, `gemini_cli`, `unknown`) |
| `source` | `text` | `otel_log` \| `otel_metric` \| `hook` \| `sim` — provenance & precedence |
| `kind` | `text` | Argus's taxonomy (§1.4) |
| `event_name` | `text` | vendor raw name, **normalized to the unprefixed form** (`tool_result`, `PostToolUse`) — see §1.5.1 |
| `vendor_seq` | `bigint` null | ordering tiebreak, dedup-key component |
| `tool_name` | `text` null | tool analytics |
| `tool_use_id` | `text` null | the tool-call join key |
| `decision` | `text` null | unconstrained; observed `accept`, `reject`; Argus writes `pending` for a permission request |
| `decision_source` | `text` null | unconstrained; documented `config`\|`hook`\|`user_permanent`\|`user_temporary`\|`user_abort`\|`user_reject` — **the differentiator column** |
| `tool_source` | `text` null | unconstrained; documented `builtin`\|`mcp`\|`sdk_host_builtin_mcp` |
| `query_source` | `text` null | **unconstrained text.** The only attribution of a model call to non-main work that a cost-bearing event carries (§1.9). Live-observed values: `sdk`, `generate_session_title`; documented `main`\|`subagent`\|`auxiliary` was *not* observed. |
| `model` | `text` null | cost/token analytics |
| `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens` | `bigint` null | analytics |
| `cost_usd` | `numeric(16,8)` null | analytics |
| `cost_source` | `text` null | `reported` \| `estimated` (DECISIONS.md §Cost) |
| `duration_ms` | `integer` null | latency analytics |
| `success` | `boolean` null | error rates |
| `error_type` | `text` null | error breakdown |
| `agent_id`, `parent_agent_id`, `agent_type` | `text` null | subagent tree — **hook payloads only**, never on OTel log events (§1.9) |
| `permission_mode` | `text` null | mode timeline |
| `file_path` | `text` null | file-touch view (needs `OTEL_LOG_TOOL_DETAILS=1`, which the quickstart sets, §8.2 — or a `FileChanged` hook) |
| `request_id`, `message_uuid` | `text` null | join to vendor API logs / transcripts (v2 enrichment) |
| `clock_skewed` | `boolean` | data-quality flag |
| `attrs` | `jsonb` | everything, verbatim |
| `dedup_key` | `text` | idempotency (§1.7) |

Deliberately **not** promoted: `organization.id`, `user.*`, `terminal.type`, `app.version` /
`service.version`, `app.entrypoint`, `client_request_id`, `speed`, `effort`, `prompt_length`,
`attempt`, `mcp_server_scope`, `tool_input_size_bytes`, `tool_result_size_bytes`, the
`hook_execution_*` counters, prompt/response content. They live in `attrs` and are queryable via
`attrs->>'…'`. The two `*_size_bytes` fields and the hook-latency fields are read out of `attrs` by
their consuming projection/query — that is their only reader, so they need no column on `events`.

Closed taxonomy. Unknown inputs map to `unknown` — **never dropped**. This is not a theoretical

OTLP metric data points are **not** events. They live only in `metric_samples` (§1.8) and have no
`Kind`: there is no `metric.sample` kind, because no metric is ever mirrored into `events` and a
permanently-dead enum branch would fail the `exhaustive` linter for nothing.

### 1.5 Mapping tables

#### 1.5.1 Claude Code OTel log events → Argus

**Event-name normalization (from the live capture).** A record's `body` is the *prefixed* form
(`"claude_code.api_request"`) while its `event.name` attribute is the *unprefixed* form
(`"api_request"`). A normalizer keyed only on `claude_code.*` would match nothing. Resolution
order for the event name:

1. `LogRecord.EventName` (the OTLP 1.x field), else
2. the `event.name` attribute, else
3. the record `body` when it is a string.

Then strip a leading `claude_code.` and store the **unprefixed** form in `events.event_name`.
`vendor` is set from the record's `service.name` resource attribute (`claude-code` → `claude_code`),
defaulting to `unknown`.

Common attributes applied to every row: `session.id → session_id`, `prompt.id → prompt_id`,
`event.timestamp → ts`, `event.sequence → vendor_seq`, `source = otel_log`, everything else →
`attrs`. `sessions.app_version` falls back to the resource `service.version` when `app.version` is
absent (the capture shows it usually is).

| `event.name` | kind | Field mapping (attr → column) |
|---|---|---|
| `user_prompt` | `turn.start` | — (`prompt_length`, `message.uuid` stay in `attrs`; content only under `OTEL_LOG_USER_PROMPTS=1`) |
| `assistant_response` | `assistant.message` | `message.uuid → message_uuid` |
| `api_request` | `llm.request` | `model`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `duration_ms`, `cost_usd_micros / 1e6 → cost_usd` (preferred over `cost_usd` — more precision; fall back to `cost_usd`), `cost_source='reported'`, `request_id`, `query_source`, `success=true` |
| `api_error` | `llm.error` | `model`, `duration_ms`, `error_type` (else `attrs.status_code`), `request_id`, `query_source`, `success=false` |
| `api_refusal` | `llm.refusal` | `model`, `error_type = attrs.category`, `success=false` |
| `api_request_body` | `llm.request_body` | none (raw only) |
| `api_response_body` | `llm.response_body` | none (raw only) |
| `tool_result` | `tool.result` | `tool_name`, `tool_use_id`, `success`, `duration_ms`, `error_type` (`attrs.error` kept too — the capture shows both), `decision_source`, `file_path = attrs.tool_parameters.file_path`, `agent_type = attrs.tool_parameters.subagent_type`; `tool_input_size_bytes` / `tool_result_size_bytes` read from `attrs` by the `tool_calls` upsert. `tool_parameters` / `tool_input` require `OTEL_LOG_TOOL_DETAILS=1`. |
| `tool_decision` | `tool.decision` | `tool_name`, **`tool_use_id`** (live-capture-verified 2026-08-11 — see below), `decision`, `decision_source = attrs.source`, `tool_source` |
| `permission_mode_changed` | `permission.mode_changed` | `permission_mode = attrs.to_mode` (`from_mode` in `attrs`) |
| `hook_registered` | `hook.registered` | none promoted (`hook_event`, `hook_matcher`, `hook_type`, `hook_source`, `plugin.name` in `attrs`) |
| `hook_execution_start` | `hook.execution_start` | none promoted (`hook_event`, `hook_name`, `num_hooks` in `attrs`) |
| `hook_execution_complete` | `hook.execution_end` | `duration_ms = attrs.total_duration_ms`, `success = (attrs.num_non_blocking_error = 0 AND attrs.num_cancelled = 0)` |
| `auth` | `agent.auth` | `success` if present |
| `mcp_server_connection` | `mcp.connection` | `success` if present |
| `internal_error` | `agent.internal_error` | `error_type`, `success=false` |
| `plugin_installed`, `plugin_loaded` | `agent.plugin` | — |
| anything else | `unknown` | common attrs only; surfaced by `/api/v1/quality/unknown-kinds` |

**`tool_decision` carries `tool_use_id` — verified, not assumed.** The live capture
(`docs/research/live-capture-2026-08-11.md` §2) observed these attribute keys on every
`tool_decision` record in both sessions: `user.id`, `session.id`, `organization.id`, `user.email`,
`user.account_uuid`, `user.account_id`, `terminal.type`, `event.name`, `event.timestamp`,
`event.sequence`, `prompt.id`, `decision`, `source`, `tool_name`, `tool_use_id`, `tool_source`,
`tool_parameters`. Review finding M10 is therefore resolved in favour of the exact-join design, and
§1.6's guarantee holds as a verified property rather than an assumption.

Other notes:
- **No OTel log event carries `agent_id` or `parent_agent_id`** (capture §3). Those exist only on
  hook payloads and on beta traces (not ingested). Consequences in §1.9.
- Cost is **only** on `api_request`. Do not derive per-event cost anywhere else.
- `tool_decision` is the only event documented to carry the 6-valued `source`. When it and
  `tool_result` both supply `decision_source` for one call, `tool_decision` wins (§1.5.3).

#### 1.5.2 Claude Code hook events → Argus

Hook transport: native `"type": "http"` POST. Common payload fields: `session_id → session_id`,
`prompt_id → prompt_id`, `hook_event_name → event_name`, `cwd`, `permission_mode →
permission_mode`, `effort.level`, `transcript_path`; subagent payloads add `agent_id → agent_id`,
`agent_type → agent_type`. `vendor = claude_code`, `source = hook`, `ts = now()` at receipt (hooks
are synchronous, so receipt time is within milliseconds) unless the payload carries a timestamp.

Because hook `ts` is receipt time and therefore differs between two deliveries of the same payload,
hook idempotency **cannot** rest on any `ts`-bearing key — it rests on the `ingest_dedup` ledger
(§1.7 rule 2).

| `hook_event_name` | kind | Extra mapping |
|---|---|---|
| `SessionStart` | `session.start` | `attrs.source → sessions.start_type`, `cwd → sessions.cwd` |
| `SessionEnd` | `session.end` | `attrs.reason → sessions.end_reason` |
| `Setup` | `agent.setup` | — |
| `UserPromptSubmit` | `turn.start` | prompt text (if sent) → `attrs` only |
| `Stop` | `turn.end` | `success = true` |
| `StopFailure` | `turn.end` | `success = false`, `error_type` |
| `PreToolUse` | `tool.pre` | `tool_name`, `tool_use_id` **if present** [unverified-safe], `agent_id` when inside a subagent, `file_path` from tool input for known file tools |
| `PostToolUse` | `tool.result` | `tool_name`, `tool_use_id` if present, `agent_id`, `success = true` |
| `PostToolUseFailure` | `tool.result` | `success = false`, `error_type` |
| `PostToolBatch` | `tool.batch` | — |
| `PermissionRequest` | `tool.permission_request` | `tool_name`, `decision = 'pending'` |
| `PermissionDenied` | `tool.decision` | `tool_name`, `decision = 'reject'`, `decision_source = 'unknown'` (the hook does not state *who* denied; the OTel `tool_decision` does — do not guess) |
| `SubagentStart` | `subagent.start` | `agent_id`, `agent_type`, `parent_agent_id` if present |
| `SubagentStop` | `subagent.stop` | `agent_id`, `success` |
| `TaskCreated` / `TaskCompleted` | `task.created` / `task.completed` | `attrs.task_id`, `success` |

| `CwdChanged` | `workspace.cwd_changed` | `attrs.cwd → sessions.cwd` update |
| `DirectoryAdded` | `workspace.directory_added` | `file_path` |
| `ConfigChange` | `workspace.config_changed` | — |
| `InstructionsLoaded` | `workspace.instructions_loaded` | — |
| `WorktreeCreate` / `WorktreeRemove` | `workspace.worktree_created` / `_removed` | `file_path` |
| `PreCompact` / `PostCompact` | `context.compact_start` / `_end` | — |
| `UserPromptExpansion` | `turn.prompt_expanded` | — |
| `Elicitation` / `ElicitationResult` | `mcp.elicitation` / `_result` | — |
| `Notification` | `agent.notification` | — |
| `MessageDisplay` | *dropped by default* | high volume, 10 s timeout budget, no analytic value. Enabled by `ARGUS_INGEST_HOOK_ALLOW_MESSAGE_DISPLAY=true`. |
| anything else | `unknown` | common fields only |

**Hook payload field names beyond the common set are [unverified-safe].** The normalizer reads them
defensively: a missing field yields `NULL`, never an error, never a rejected request. Every hook
body is preserved in `attrs` in full, so a mapping correction is a projection rebuild, not data
loss.

Recommended hook config shipped in the README. Note the `SessionEnd` timeout: the **shared budget
across all `SessionEnd` hooks is 1.5 s**, so teaching `5` there would be wrong even though Argus
ACKs in milliseconds.

```jsonc
{ "hooks": {
  "PostToolUse": [ { "hooks": [
    { "type": "http", "url": "http://localhost:8080/ingest/hook", "timeout": 5 } ] } ],
  // SessionEnd hooks share a hard 1.5 s budget — keep this at 1.
  "SessionEnd":  [ { "hooks": [
    { "type": "http", "url": "http://localhost:8080/ingest/hook", "timeout": 1 } ] } ]
} }
```

#### 1.5.3 Precedence when both surfaces describe one moment

The events table stores **both** rows. Merging happens in two places only:

**(a) Projection field precedence** — when OTel and hook rows disagree:

| Projection field | Winner | Reason |
|---|---|---|
| `sessions.started_at` / `ended_at` | earliest / latest observed, any source | monotonic facts |
| `sessions.start_type`, `end_reason` | hook | OTel has `start_type` only as a metric attribute |
| `sessions.cwd`, `project` | hook (`SessionStart.cwd`, `CwdChanged`) | OTel `workspace.host_paths` is a list and less direct |
| `sessions.app_version`, `entrypoint`, `terminal_type`, `user_*`, `org_id` | otel_log (falling back to resource `service.version` for the version) | hooks don't carry them |
| `tool_calls.decision`, `decision_source`, `tool_source` | `otel_log`/`tool_decision` > `otel_log`/`tool_result` > `hook` | only `tool_decision` carries the authoritative 6-valued `source` |
| `tool_calls.duration_ms`, `input_size_bytes`, `result_size_bytes` | otel_log (`tool_result`, read from `attrs`) | measured by the agent |
| `tool_calls.started_at` | earliest of `tool.pre` / `tool.decision` | hook `PreToolUse` fires first |
| `tool_calls.success`, `error_type` | otel_log > hook | richer error vocabulary |
| `tool_calls.agent_id` | hook | the only source (§1.9) |
| `turns.*` cost/tokens | always aggregated from `llm.request` events only | never from hooks |
| `subagents.*` | hook (`SubagentStart/Stop` are the only source) | OTel emits no subagent lifecycle event |

Implemented as `COALESCE`-with-rank in the upsert: each projection row carries a `field_ranks`
jsonb holding the source rank that last wrote each precedence-governed column; a write overwrites
only when its rank is ≥ the stored rank (equal rank ⇒ later `ts` wins). Ranks: `otel_log=30`,
`hook=20`, `otel_metric=10`, `sim` = the rank of the source it imitates.

**(b) UI timeline collapse** — the timeline endpoint returns raw events; the frontend collapses a
group into one row when all of: same `kind`, same correlation key (`tool_use_id`, else `prompt_id`,
else `session_id`), and `|Δts| ≤ 2000 ms`. The collapsed row shows the union of fields with the
precedence above and exposes a "2 sources" affordance listing the raw events. Collapsing is
**display-only and reversible** (`?collapse=false`): the rule is heuristic, and users debugging
their own pipeline need the raw stream.

### 1.6 Projections

| Table | Key | Built from |
|---|---|---|
| `sessions` | `id` | `session.*` events + first/last event seen + aggregates of `llm.request` |
| `turns` | `(session_id, prompt_id)` | `turn.*` + aggregates of events carrying that `prompt_id` |
| `tool_calls` | `id uuid` (deterministic, below), unique `(session_id, tool_use_id)` when non-null | `tool.pre` / `tool.decision` / `tool.permission_request` / `tool.result` |
| `subagents` | `(session_id, agent_id)` | `subagent.*`, plus hook `tool.*` events carrying `agent_id` |

Projections are updated **synchronously in the same transaction as the event insert batch**. This is
a deliberate choice over an async projector: it removes a whole class of "UI is behind" bugs, and at
this scale (a personal/team tool: order 10²–10⁴ events/min worst case) the extra upsert cost is
irrelevant. Full rebuild for schema/mapping changes: `argusd rebuild-projections [--from-ts …]`
replays events in `(ts, seq)` order.

**Deterministic projection ids.** `tool_calls.id` is computed in Go as UUIDv5 (`uuid.NewSHA1`) over
a fixed Argus namespace UUID and the string `session_id|tool_use_id` — or, when `tool_use_id` is
absent, `session_id|prompt_id|tool_name|ordinal`, where `ordinal` is the 0-based index of that
(session, prompt, tool) call in `(ts, seq)` order. It is therefore reproducible by a rebuild, which
is what makes the "rebuild produces identical rows" guarantee (and its test, P3-10) meaningful.
`events.id` stays `uuidv7()` — events are never rebuilt.

**Transaction lock ordering (invariant).** Within one `WriteBatch` transaction, statements run in
this fixed order, and rows within each statement are sorted by primary key ascending:
`ingest_dedup` (by `dedup_key`) → `sessions` (by `id`) → `turns` (by `session_id, prompt_id`) →
`events` (by `ts, dedup_key`) → `tool_calls` (by `id`) → `subagents` (by `session_id, agent_id`) →
`rollup_dirty` (by `bucket, source`). Two concurrent batches touching an overlapping set of
sessions therefore acquire locks in the same order and cannot deadlock on each other. This is an
invariant, not an optimisation: violating it reintroduces the deadlock that the FK
share-lock/exclusive-lock interleaving makes likely at 4 workers × 500-event batches.

**Tool-call correlation** (`tool_calls.correlation`):

| Value | When |
|---|---|
| `exact` | joined on a non-null `tool_use_id` present in ≥1 OTel and ≥1 hook event |
| `otel_only` | `tool_use_id` present, only OTel events |
| `hook_only` | no `tool_use_id` anywhere for this call |
| `heuristic` | a *hook* event without `tool_use_id` attached to an OTel call by fallback match: same `session_id` + same `prompt_id` + same `tool_name` + nearest open call within 60 s, one-to-one |

The heuristic is confined to one function (`ingest/normalize.correlateToolCall`) and its outcome is
surfaced in the API and the UI (dotted underline + caveat on the decision badge).

**Guarantee (verified, no longer conditional).** Both OTel events that carry decision provenance —
`tool_decision` and `tool_result` — carry `tool_use_id` (live capture, §1.5.1). Therefore
**decision provenance is always an exact join and never depends on the heuristic.** The heuristic
exists solely to enrich a tool call with hook-only fields (`agent_id`, `PreToolUse` timing) when the
hook payload lacks `tool_use_id`, and the UI is fully correct when every row is `otel_only` +
`hook_only`. No v1 feature is load-bearing on `heuristic` correlation. `exact_share` is still
reported by `/api/v1/analytics/decisions` (§4.3) so the dashboard states its own confidence
rather than asking the user to trust this paragraph.

### 1.7 Out-of-order arrival, unknown parents, idempotency

Three rules, no exceptions.

1. **Stub-on-reference.** Any event insert first performs
   `INSERT INTO sessions (id, vendor, first_seen_at, status, …) VALUES (…, 'unknown', …)
   ON CONFLICT (id) DO UPDATE SET last_event_at = GREATEST(…)`, and the same for `turns` when
   `prompt_id` is present. A session row can therefore exist with `started_at IS NULL` and
   `status = 'unknown'`. The API and UI render these normally (labelled *partial*). A later
   `session.start` fills the gaps via the rank rule. Nothing waits, nothing is buffered, nothing is
   rejected for a missing parent.

2. **Idempotency: a non-partitioned `ingest_dedup` ledger is the gate.** Receipt-time `ts` on hook
   events makes any `ts`-bearing unique key useless for hook dedup, so the ledger is the single
   mechanism for all sources:

   ```sql
   INSERT INTO ingest_dedup (dedup_key)
   SELECT unnest($1::text[])          -- sorted ascending; see the lock-ordering invariant
   ON CONFLICT (dedup_key) DO NOTHING
   RETURNING dedup_key;               -- ⇒ exactly the keys not seen before
   ```

   Only events whose key came back are inserted into `events`; the rest increment
   `argus_ingest_deduped_total`. Verified on PG 18.4. The events insert additionally carries
   `ON CONFLICT (ts, dedup_key) DO NOTHING` against a **parent-level** unique constraint (§2.2) as
   defence in depth.

   Key construction:
   - `otel_log`: `otel:{session_id}:{vendor_seq}:{event_name}:{sha256_16(canonical_record)}`.
     `event.sequence` is verified per-session monotonic (§1.2), so the first three components are
     already a valid key; the content hash is kept as cheap insurance — a future regression in that
     counter would otherwise collapse two distinct events into one with no error. When `vendor_seq`
     is absent, the **hash form** is used: `otel:{session_id}:h:{sha256_16(canonical_record)}`.
   - `otel_metric`: `metric:{sha256_16(name|ts|canonical_attrs)}`
   - `hook`: `hook:{sha256_16(hook_event_name|session_id|prompt_id|canonical_json(body))}`
   - `sha256_16` = first 16 bytes of SHA-256, hex. `canonical_*` = JSON with sorted keys and no
     insignificant whitespace, so hashing is stable across map iteration order.

   **Guarantee and its limit**: dedup is exact within `ARGUS_DEDUP_WINDOW` (default `7d`), the
   ledger's retention. Retransmits and duplicate hook-config scopes both occur within milliseconds,
   so 7 days is generous; the trade-off is ledger size (~90 bytes/event). Beyond the window a
   re-sent hook event may duplicate; a re-sent OTel event still cannot, because its `ts` is
   agent-supplied and stable and the parent unique constraint catches it.

3. **Late data is accepted, rollups self-heal.** Every batch marks the hour buckets it touched in
   `rollup_dirty` **inside the same transaction** (§2.4), so no bucket can be missed by pre-commit
   sequence allocation. Events whose `ts` precedes the retention cutoff have no partition to land
   in; the insert errors, the offending rows are dropped, and `argus_ingest_too_old_total` is
   incremented. There is **no `DEFAULT` partition** — a silent catch-all would make `too_old`
   undetectable, and the clamp in §1.2 already guarantees only genuinely-expired events reach this
   path.

Status is a **stored column**, not a read-time derivation (this is what makes `?status=` filtering,
`ORDER BY`, and the `sessions (status, last_event_at DESC)` index real): `unknown` on a stub,
`active` once `started_at` is known, `ended` when a `session.end` arrives, and `abandoned` by a
periodic sweep (`UPDATE sessions SET status='abandoned' WHERE status IN ('active','unknown') AND
ended_at IS NULL AND last_event_at < now() - ARGUS_SESSION_IDLE_TIMEOUT`). A `session.end` arriving
after the sweep moves the row back to `ended`. This handles the common case of a crashed CLI that
never fires its `SessionEnd` hook.

### 1.8 OTel metrics vs log events

**Decision: log events are the per-event source of truth for cost, tokens, and everything
attributable to a turn. Metrics are stored raw and feed only (a) rollup series that log events
cannot produce, and (b) a degraded mode when the logs exporter is off.**

Justification (one paragraph): the two surfaces overlap on cost and tokens but the metric form is
strictly weaker for Argus's purpose — `claude_code.cost.usage` and `token.usage` are batched at a
60 s default interval, carry no `prompt.id` and no `tool_use_id`, are subject to
`OTEL_METRICS_INCLUDE_SESSION_ID=false` (so may not even be attributable to a session), and are
temporality-dependent, whereas `api_request` log events carry `cost_usd_micros`, all four token
types, `model`, `duration_ms`, `request_id`, `query_source`, `session.id` *and* (per the live
capture) `prompt.id` per call at a 5 s export interval. Summing both would double-count, and
choosing metrics would destroy turn-level attribution — the core of the product. Conversely, three
metric series have **no log-event equivalent at all** (`lines_of_code.count`, `active_time.total`,
`commit.count`/`pull_request.count`) and one is a cheap cross-check
(`code_edit_tool.decision`), so metrics are not discardable either.

| Metric | Stored in `metric_samples` | Feeds rollups |
|---|---|---|
| `claude_code.cost.usage` | yes | only into `rollup_*` rows with `source='metric'` — a separate row from `source='event'`, never summed with it |
| `claude_code.token.usage` | yes | same as above |
| `claude_code.lines_of_code.count` | yes | **yes** → `loc_added` / `loc_removed` |
| `claude_code.active_time.total` | yes | yes → `active_seconds` |
| `claude_code.commit.count`, `pull_request.count` | yes | yes → `commits`, `pull_requests` |
| `claude_code.session.count` | yes | no (sessions counted from the `sessions` table) |
| `claude_code.code_edit_tool.decision` | yes | yes → `edit_decisions_{accept,reject}` (cross-check panel only) |
| unknown metric name | yes | no |

No metric is ever mirrored into `events`. Rollup rows carry `source ∈ ('event','metric')` in their
primary key; the analytics API defaults to `source=event` and exposes `source=metric` explicitly;
the UI never adds them. A "logs exporter appears to be off" banner shows when a project has
`metric` rows and zero `event` cost rows in the window — turning the most likely misconfiguration
into a visible hint rather than a silently empty dashboard.

**Temporality.** The README instructs `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE=delta`.
Cumulative is still handled: `metric_series_state(series_hash, last_ts, last_value)` lets the rollup
job diff consecutive cumulative points; a negative diff is treated as a counter reset and the raw
value is taken. Gauges are last-value-wins per bucket.

### 1.9 Subagent and non-main attribution — what is knowable in v1

This section exists because the available telemetry is weaker than the feature it is asked to
support, and pretending otherwise would produce a dashboard reading `$0.00` for every subagent.

**Verified facts** (live capture §3): cost and tokens appear only on `api_request`. That event
carries `query_source` but **no `agent_id`**. `agent_id`/`parent_agent_id` appear only on hook
payloads (`SubagentStart/Stop`, and tool hooks fired inside a subagent) and on beta traces, which
v1 does not ingest. Further, **`query_source`'s real vocabulary is not the documented one**: the
capture observed `sdk` and `generate_session_title`, never `main`/`subagent`/`auxiliary`.

**Therefore, in v1:**

| Quantity | Available? | How |
|---|---|---|
| Cost split by `query_source` | **yes, but uninterpreted** | `sessions.cost_by_query_source jsonb` — a map from the raw observed `query_source` value (`""` for absent) to summed cost. Argus does **not** map these values onto a "subagent vs main" semantic, because the real vocabulary is unknown and version-dependent. |
| "Non-primary" cost | **yes, weakly** | the share of cost whose `query_source` differs from the session's dominant (highest-cost) value. Presented as *"other query sources: $X of $Y"* with the raw value names listed. This is the honest form of the claim. |
| Subagent tree shape, types, lifecycle, durations, status | **yes** | hook `SubagentStart`/`SubagentStop` |
| Per-*node* tool call count | **only with hooks enabled** | hook `tool.*` events carrying `agent_id`; `NULL` (rendered `—`) when the session has no hook coverage — never `0`, which would be a lie |
| Per-*node* cost / tokens | **no** | columns exist and stay `NULL`; the UI renders `—` with a tooltip explaining that Claude Code does not emit per-agent cost |

Consequences that are binding on implementers:
- `query_source` is an **unconstrained text column** — no enum, no `CHECK`, no Go constant set that
  can reject a value, and no UI string that assumes a specific value exists.
- No v1 UI feature is load-bearing on a particular `query_source` value.
- **`argus-sim` must not emit `agent_id` on `api_request`/`tool_result` OTel events** (§7). It emits
  `query_source` with realistic variety *including values Argus has never seen*, so the "unknown
  vocabulary" path is exercised by default rather than being a theory. A simulator that invents an
  attribute makes an unimplementable feature look green in every test and demo, and the failure then
  surfaces only when the owner points real Claude Code at it.
- Any test asserting per-node cost, or "root aggregates = session totals minus children", is
  invalid.

```sql
                                  -- constraint on the partitioned table itself. Postgres creates
                                  -- the per-partition indexes automatically.
) PARTITION BY RANGE (ts);
```

The parent-level `UNIQUE (ts, dedup_key)` is legal because it contains the partition key, and it is
mandatory: a per-partition unique index does **not** satisfy
`INSERT INTO events … ON CONFLICT (ts, dedup_key)`, which fails with *"there is no unique or
exclusion constraint matching the ON CONFLICT specification"* — reproduced on PG 18.4, and the
parent-level form verified to work and to auto-create `events_YYYY_MM_ts_dedup_key_key`. It is
defence in depth behind the `ingest_dedup` ledger (§1.7 rule 2), which is the actual gate.

No FK from `events` to `sessions`: partition-wide FK enforcement costs write throughput and
stub-on-reference already guarantees the parent row. Referential integrity is a store-layer
invariant, integration-tested.

**Partitioning: monthly RANGE on `ts`.** Monthly (not daily) because 90 days of a personal/team tool
is ~4 partitions — daily would mean 90 planning-time partitions for a marginal pruning win.
Retention granularity is therefore coarse (a partition drops only when *entirely* older than the
cutoff), which is documented and acceptable; a `--precise` retention mode additionally `DELETE`s in
batches within the boundary partition. **There is no `DEFAULT` partition** — an out-of-range insert
must error so it can be classified `too_old` (§1.7 rule 3).

Per-partition indexes created by the partition manager (**6**; the unique index on
`(ts, dedup_key)` is *inherited* from the parent constraint and must not be created again):

```sql
CREATE INDEX ON events_YYYY_MM (session_id, ts, seq);        -- session timeline (hottest read)
CREATE INDEX ON events_YYYY_MM (kind, ts DESC);              -- live filter by kind; rollups;
                                                             -- unknown-kind inspector
CREATE INDEX ON events_YYYY_MM (session_id, tool_use_id)
    WHERE tool_use_id IS NOT NULL;                            -- tool-call correlation
CREATE INDEX ON events_YYYY_MM (session_id, prompt_id)
    WHERE prompt_id IS NOT NULL;                              -- turn detail
CREATE INDEX ON events_YYYY_MM (ingested_at);                 -- ingest-lag + data-quality
                                                              -- (NO `kind <> 'unknown'` predicate:
                                                              -- the inspector needs those rows)
CREATE INDEX ON events_YYYY_MM (decision_source)
    WHERE decision_source IS NOT NULL;                        -- decision-provenance analytic
```

SSE replay does **not** use the `ingested_at` index: its predicate is
`ts >= $windowStart AND (ts, seq) > ($ts, $seq)`, which rides the primary key and prunes partitions
(§5.2).

Not created: a GIN index on `attrs`, and any index on `events.id`. `attrs` queries in v1 are all
inside one session (already narrowed by the session index) or ad-hoc SQL, and GIN would roughly
double write amplification for no v1 query. Single-event fetches address `(ts, seq)` via
`event_ref` (§1.2), so `id` needs no index.

```sql
    model                  text NOT NULL,
    effective_from         date NOT NULL,
    currency               text NOT NULL DEFAULT 'USD',
    input_per_mtok         numeric(12,6) NOT NULL,
    output_per_mtok        numeric(12,6) NOT NULL,
    cache_read_per_mtok    numeric(12,6) NOT NULL DEFAULT 0,
    cache_write_per_mtok   numeric(12,6) NOT NULL DEFAULT 0,
    source                 text NOT NULL DEFAULT 'repo',    -- repo|user
    PRIMARY KEY (model, effective_from)
);
-- lookup: latest effective_from <= event date, exact model, else longest matching prefix

CREATE TABLE job_state (
    job          text PRIMARY KEY,   -- 'rollup'|'retention'|'partitions'|'sweep'|'rebuild'
    last_run_at  timestamptz,
    last_error   text,
    watermark    bigint,             -- used ONLY by rebuild-projections for resumption
    watermark_ts timestamptz
);
```

Rollups deliberately carry **no `query_source` dimension**: its real vocabulary is unknown (§1.9),
so putting it in a primary key would make cardinality a function of an undocumented agent
behaviour. The cost split by `query_source` lives on `sessions` only, where it is cheap and where
the subagent view actually needs it.

**Rollup job.** Every `ARGUS_ROLLUP_INTERVAL` (default 60 s), single-flight via
`pg_try_advisory_lock`, entirely inside one transaction so a failure restores the work queue:

1. `BEGIN`; take the advisory lock.
2. Claim dirty buckets: `DELETE FROM rollup_dirty WHERE (bucket, source) IN (SELECT bucket, source
   FROM rollup_dirty ORDER BY bucket LIMIT $max) RETURNING bucket, source` — capped by
   `ARGUS_ROLLUP_MAX_BUCKETS` (default 200) to bound a backfill.
3. Union in the **current and previous hour unconditionally** (belt-and-braces against a missed
   dirty mark, and it keeps the live dashboard fresh).
4. For each claimed bucket: **full recompute of that bucket** — `INSERT … SELECT … ON CONFLICT (pk)
   DO UPDATE SET <all metrics> = EXCLUDED.*`. Idempotent, late-data-safe, and the only correct
   choice given out-of-order arrival. The `event` pass joins `events → sessions` for `project`.
5. Recompute `rollup_daily` for the affected days from `rollup_hourly`.
6. `COMMIT`. On rollback the dirty rows are still there and the next run retries them.

**Why there is no `events.seq` watermark.** Identity values are allocated *before* commit, so a
watermark on `seq` permanently loses buckets under concurrent ingest: worker A takes seq 100,
worker B takes 101 and commits first, the job advances past 101, then A commits and its bucket is
never re-dirtied. Since §2.5 forbids request-time aggregation over `events`, that loss would be
silent and permanent in the #2 v1 feature. The transactional `rollup_dirty` queue has no such
window: the dirty mark and the events commit atomically together.

**Dirty-marking rules** (all inside the writing transaction):
- every batch marks `date_trunc('hour', ts)` for each distinct `ts` hour it inserts,
  `source='event'`; metric batches do the same with `source='metric'`;
- **when a session's `project` or `cwd` changes** (the late-`SessionStart` case — OTel batches at
  5 s while hooks fire synchronously, so events routinely precede the hook that names the project),
  the session upsert marks every hour bucket from `first_seen_at` to `last_event_at` dirty, capped
  at `ARGUS_ROLLUP_SESSION_REMARK_MAX` (default 720 = 30 days) with a warning if exceeded. Without
  this, such a session's cost stays attributed to `project=''` forever.

Cost in rollups: `cost_reported_usd` = `SUM(cost_usd) WHERE cost_source='reported'`;
`cost_estimated_usd` = for `llm.request` rows with `cost_usd IS NULL`, tokens × `model_prices`
resolved at event date. Never summed into one column at the storage layer; the API exposes
`cost_usd = reported + estimated` plus `estimated_share` so the UI can flag it.

**Partition manager job.** Hourly. Ensures partitions exist for the current month and the next two
(`CREATE TABLE IF NOT EXISTS … PARTITION OF …` plus the 6-index set for `events` / 2-index set for
`metric_samples`). No `DEFAULT` partition. Startup fails loudly if the current month's partition
cannot be created.

**Backward creation, decided 2026-08-13; implemented in Phase 3 (P3-12).** The job also ensures
partitions exist backward from the current month to the retention horizon
(`ARGUS_RETENTION_RAW_DAYS`), not just forward to current+2: an in-retention backfill (e.g. a
14-day replay crossing a month boundary) must never hit a missing partition and be misclassified
`too_old`. `too_old` (§1.7 rule 3) remains reserved for data genuinely older than the retention
horizon. As of this deviation's acceptance, `EnsurePartitions` only creates forward from `from` to
`to`; the caller in `internal/app/jobs.go` passes `(now, now+2mo)` and does not yet reach backward
— P3-12 changes the caller (not `EnsurePartitions`'s signature) to also pass the retention floor.

**Retention job.** Daily at `ARGUS_RETENTION_HOUR` (default 04:00 local):
- drops `events` / `metric_samples` partitions whose upper bound ≤ `now() −
  ARGUS_RETENTION_RAW_DAYS` (default 90);
- prunes `ingest_dedup` where `first_seen_at < now() − ARGUS_DEDUP_WINDOW` (default 7 d) in bounded
  batches;
- optionally deletes `sessions` older than `ARGUS_RETENTION_SESSION_DAYS` (default 0 = never),
  cascading to `turns`/`tool_calls`/`subagents`.

Rollups and projections are never deleted by raw retention, so a 3-year-old session keeps its row
and aggregates with an empty timeline (the UI says "raw events expired"). Dry-run:
`argusd retention --dry-run`.

**Abandoned-session sweep.** Same scheduler, every `ARGUS_SWEEP_INTERVAL` (default 60 s), using
`sessions_sweep_idx` (§2.1, §1.7).

### 2.5 Query patterns → index map

| Query (v1 endpoint) | Plan |
|---|---|
| session list, filtered + keyset, any of 4 sort keys | the eight `sessions_*` indexes (§2.1) |
| abandoned sweep | `sessions_sweep_idx` (partial) |
| session timeline | `events (session_id, ts, seq)` — monthly partitions pruned by the window |
| single event by `event_ref` | `events` PK `(ts, seq)`, one partition |
| tool calls of a session / of a subagent | `tool_calls (session_id, started_at)` / `(session_id, agent_id)` |
| subagent tree | `subagents (session_id, parent_agent_id)` + recursive CTE |
| analytics summary / timeseries / breakdown | `rollup_hourly (bucket DESC)` / `(project, bucket DESC)` — never touches `events` |
| decision breakdown | `rollup_hourly` for counts; `tool_calls (decision, decision_source, started_at DESC)` for the drill-down |
| SSE replay | `events` PK, bounded `ts >= now() − replay_window` |
| data-quality counters (`unknown` kinds, skew, lag) | `events (kind, ts DESC)` and `events (ingested_at)`, both bounded to 24 h |
| hook-latency panel | `events (kind, ts DESC)` on `hook.execution_end`, bounded to the window |

Every analytics read hits a rollup. **No v1 endpoint aggregates over `events` at request time**;
asserted by an integration test that runs `EXPLAIN` on each analytics query and fails if `events`
appears in the plan. The data-quality and hook-latency queries are exempt and explicitly listed in
that test's allow-list, bounded to their windows.

### 3.3 The storage seam

```go
package store

type Store interface {
    Writer
    Reader
    Maintenance
    Health(ctx context.Context) error
    Close()
}

// Writer is what ingest needs. Batches are the unit of work.
type Writer interface {
    // WriteBatch gates on ingest_dedup, inserts events, and updates all projections plus
    // rollup_dirty in ONE transaction, honouring the lock-ordering invariant (§1.6). Returns
    // per-event outcomes so ingest can count dedup suppressions and fan out to stream only the
    // events that were actually persisted.
    WriteBatch(ctx context.Context, b []model.Event) (BatchResult, error)

    // WriteMetrics is a P2-06 deviation, accepted 2026-08-13: this section originally listed
    // only WriteBatch, but §1.8/§2.3 require OTel metric data points to land in metric_samples,
    // and they arrive as []model.MetricSample, never model.Event (no Kind exists for a metric,
    // §1.4). WriteMetrics gates on the same ingest_dedup ledger (the "metric:" key form), inserts
    // into metric_samples, and marks rollup_dirty with source='metric', in the same relative
    // lock order as WriteBatch (dedup -> metric_samples -> rollup_dirty).
    WriteMetrics(ctx context.Context, samples []model.MetricSample) (BatchResult, error)
}

type Reader interface {
    ListSessions(ctx context.Context, f SessionFilter, p Page) ([]model.SessionSummary, Cursor, error)
    GetSession(ctx context.Context, id string) (*model.SessionDetail, error)
    ListTurns(ctx context.Context, sessionID string) ([]model.Turn, error)
    ListEvents(ctx context.Context, f EventFilter, p Page) ([]model.Event, Cursor, error)
    GetEvent(ctx context.Context, ref model.EventRef) (*model.Event, error) // PK lookup (ts, seq)
    ListToolCalls(ctx context.Context, f ToolCallFilter, p Page) ([]model.ToolCall, Cursor, error)
    SubagentTree(ctx context.Context, sessionID string) (model.SubagentTree, error)
    AnalyticsSummary(ctx context.Context, f AnalyticsFilter) (model.Summary, error)
    AnalyticsSeries(ctx context.Context, f AnalyticsFilter, g Grouping) (model.Series, error)
    AnalyticsBreakdown(ctx context.Context, f AnalyticsFilter, d Dimension) (model.Breakdown, error)
    AnalyticsDecisions(ctx context.Context, f AnalyticsFilter) (model.DecisionMatrix, error)
    // EventsSince is bounded by ts so it rides the (ts, seq) primary key and prunes partitions.
    EventsSince(ctx context.Context, after model.EventRef, windowStart time.Time, limit int) ([]model.Event, error)
    Facets(ctx context.Context) (model.Facets, error)
    DataQuality(ctx context.Context) (model.DataQuality, error)
    UnknownKinds(ctx context.Context, since time.Time, limit int) ([]model.UnknownKindGroup, error)
    HookLatency(ctx context.Context, f AnalyticsFilter) (model.HookLatency, error)
}

type Maintenance interface {
    Migrate(ctx context.Context) error
    EnsurePartitions(ctx context.Context, from, to time.Time) error
    RunRollups(ctx context.Context, max int) (RollupStats, error)
    SweepAbandoned(ctx context.Context, idle time.Duration) (int64, error)
    ApplyRetention(ctx context.Context, cutoff time.Time, dryRun bool) ([]string, error)
    PruneDedup(ctx context.Context, cutoff time.Time) (int64, error)
    RebuildProjections(ctx context.Context, fromTS time.Time) error
}
```

Implementations: `postgres.Store` (production) and `storetest.Fake` (in-memory, for httpapi and
stream unit tests — not for store tests). ClickHouse in v2 implements `Writer`+`Reader`;
`Maintenance` is allowed to be backend-specific and is reached through a type assertion in the job
scheduler, not through the common interface. Query construction: sqlc for everything fixed; the

### 3.4 OTLP/HTTP receiver

Mounted at the root so `OTEL_EXPORTER_OTLP_ENDPOINT=http://argus:8080` works with zero extra config
(the OTel SDK appends `/v1/logs` itself):

| Route | Behaviour |
|---|---|
| `POST /v1/logs` | ingest |
| `POST /v1/metrics` | ingest |
| `POST /v1/traces` | accept, discard, count `argus_otlp_traces_discarded_total`, return an empty `ExportTraceServiceResponse`. Traces are out of scope (DECISIONS.md), but silently 404-ing an exporter causes noisy client-side error loops; accepting and dropping is friendlier and documented. |

Content negotiation: `application/x-protobuf` → `proto.Unmarshal`; `application/json` →
`protojson.Unmarshal` with `DiscardUnknown: true` (mandatory — Claude Code adds fields, as the
capture's three undocumented events demonstrate). Other types → 415. `Content-Encoding: gzip`
supported, with `ARGUS_INGEST_MAX_BODY_BYTES` (default 8 MiB) enforced on the *decompressed* stream
to prevent zip bombs; `http.MaxBytesReader` before decode.

Responses follow the OTLP/HTTP spec: full success → `200` + empty `Export*ServiceResponse`; records
that cannot be attributed to a session at all → `200` + `partial_success{rejected_log_records: N,
error_message}` (anything else is stored, possibly as `kind='unknown'`); queue full → `503` +
`Retry-After: 1` (the SDK retries with backoff — exactly the desired backpressure); malformed
protobuf → `400` with an `application/x-protobuf` `Status`.

Decode path: walk `ResourceLogs → ScopeLogs → LogRecord`; merge resource/scope attributes with
record attributes (record wins); keep resource attributes (`service.name`, `service.version`,
`os.type`, …) in `attrs` under a `resource.` prefix. Event-name resolution follows §1.5.1
(`EventName` → `event.name` attr → `body`, then strip the `claude_code.` prefix).
`LogRecord.TimeUnixNano` is preferred over the `event.timestamp` string (fewer parse failures);
disagreement > 5 s raises `clock_skewed`.

### 3.5 Hooks webhook

`POST /ingest/hook`, JSON, one payload per request (Claude Code sends one); also accepts an array
for batch replay by `argus-sim`.

**The 1.5 s `SessionEnd` budget dictates the design**: the handler validates `session_id`, computes
the dedup key, enqueues, and returns `202 Accepted` with `{"ok":true,"event":"<hook_event_name>"}`.
It never touches the database. Target p99 < 20 ms, guarded by
`argus_hook_handler_duration_seconds` and a test asserting the handler makes zero store calls.
Queue full → `429` + `Retry-After: 1`; Claude Code does not retry hooks, so this is counted data
loss (`argus_ingest_dropped_total{source="hook"}`) surfaced in the UI's health strip — silent loss
in an observability tool is unacceptable.

Optional shared secret: if `ARGUS_INGEST_TOKEN` is set, both OTLP and hook endpoints require
`Authorization: Bearer <token>` (constant-time compare). Unset by default (DECISIONS.md: no auth in
v1) — this is the auth-shaped seam, `httpapi/middleware.RequireIngestToken`, sitting where a real
authenticator will later go. The read API has the same seam (`ARGUS_API_TOKEN`), also unset.

Argus is observe-only: the response never contains a hook *decision* field. Blocking or intervening
is explicitly a non-goal.

### 3.6 Pipeline: batching and backpressure

```
handler → normalize (in the request goroutine; cheap, pure, testable)
        → queue: chan []model.Event  (cap ARGUS_INGEST_QUEUE=1024 batches)
        → N workers (ARGUS_INGEST_WORKERS=4)
             accumulate until ARGUS_INGEST_BATCH_SIZE=500 events or ARGUS_INGEST_FLUSH=250ms
             → store.WriteBatch (one tx, fixed lock order §1.6)
             → stream.Hub.Publish(persisted events)
```

- Normalization happens **before** enqueue so a malformed payload fails fast with a 400 and never
  occupies queue capacity.
- Non-blocking enqueue (`select` with `default`) — the queue is a shock absorber, not a buffer to
  hide a slow database in. Full queue = load shed with a correct HTTP status, always.
- **Retry classification** on `WriteBatch` failure:
  - `40P01` (deadlock) / `40001` (serialization failure) → immediately retryable, up to
    `ARGUS_INGEST_RETRY_CONFLICT` attempts (default 8), jittered backoff from 5 ms. Expected under
    concurrency; must never cost data.
  - connection/transient (`08…`, `57P01`, context deadline) → up to
    `ARGUS_INGEST_RETRY_TRANSIENT` attempts (default 3) at 100 ms / 400 ms / 1.6 s.
  - constraint/programming (`23…`, `42…`) → **do not retry**; log the batch's first event id at
    ERROR and drop, incrementing `argus_ingest_write_failed_total{class="permanent"}`.
  - **data exception (`22…`, e.g. `22P02` invalid text representation, `22003` numeric value out
    of range, `22001` string data right truncation) → do not retry**, same handling as
    constraint/programming above. Accepted 2026-08-13: this class was originally unlisted here and
    fell through to the transient default, burning the full `ARGUS_INGEST_RETRY_TRANSIENT` budget
    on a malformed value that fails identically on every attempt, and worse, counting it under
    `class="transient"` — misdirecting an operator toward a flaky database instead of a bad
    payload.
  The lock-ordering invariant makes `40P01` rare; the retry budget exists because "rare" is not
  "never", and a flat 3× policy would drop data on a routine deadlock.
- No disk spool in v1: a second storage system with its own failure modes, and Postgres being down
  for > 5 s is a visible operational failure, not something to paper over. (v2 backlog if it hurts.)
- Ordering: `seq` is assigned by Postgres, so parallel workers interleave. That is fine — `seq` is
  an ingest-order tiebreak, timeline order is `(ts, vendor_seq, seq)`, and nothing (notably not the
  rollup job, §2.4) treats `seq` as a high-water mark. Documented so nobody "fixes" it into a single
  writer.
- Self-metrics: queue depth gauge, batch-size histogram, per-source event counters, dedup counter,
  write-duration histogram, retry counters by class, `argus_ingest_lag_seconds` (`ingested_at − ts`).

`argusd <serve|migrate|sim|retention|rebuild-projections|prices|config|version|healthcheck>`. Flat
`flag` package per subcommand — no cobra. `argus-sim` is a thin second binary calling the same
`internal/sim`, because DECISIONS.md names it.

- `migrate` — `up` (default), `status`, `down-to N`. Goose over `embed.FS`; also invoked by `serve`
  when `ARGUS_AUTO_MIGRATE=true`, guarded by a Postgres advisory lock so concurrent starts are safe.
- `serve` — starts HTTP, pipeline, stream hub, and the jobs (partitions, rollups, sweep, retention)
  in an `errgroup`-shaped supervisor.
- Graceful shutdown on SIGINT/SIGTERM: (1) `/readyz` starts failing; (2) `http.Server.Shutdown`
  with `ARGUS_SHUTDOWN_GRACE` — in-flight ingest requests finish, SSE subscribers get a final
  `event: shutdown`; (3) close the ingest queue and drain it fully (same grace); (4) `pool.Close()`.
  Exit 0 only if the drain completed; 1 if events were dropped, so a compose restart loop is visible.

Self-observability: `GET /healthz` (liveness, no DB), `GET /readyz` (DB ping + migrations current +
queue not saturated), `GET /metrics` (Prometheus). In Phase 1, `/readyz` reports
`"migrations":"current"` as an assertion (no live check against `goose_db_version`); `Maintenance`
gains a status method in Phase 2 alongside the queue-saturation readiness condition. slog with
`request_id` on every line; ingest logs sampled 1/100 on success so the tool cannot DoS its own log
file.

## 4. REST API

`/api/v1`, JSON, OpenAPI 3.1 at `server/api/openapi.yaml` (hand-authored — the spec is the source of
truth and is reviewed like code; generating it from Go annotations makes it an afterthought).

### 4.1 Conventions

- **Envelope**: collections return `{ "data": [...], "page": { "next_cursor": "…"|null, "has_more": bool } }`.
  Single resources return the object bare.
- **Pagination**: keyset only. `?limit=` (default 50, max 500) + `?cursor=`. Cursor = URL-safe
  base64 of `{"k":"<sort key>","v":[…]}`; opaque, validated, 400 on tamper. No offset paging.
- **Event addressing**: every event payload carries `event_ref` (opaque base64url of `ts`+`seq`);
  `GET /api/v1/events/{ref}` fetches one event with `attrs`. There is no lookup by `id`.
- **Time params**: `from`, `to` as RFC 3339 or a relative shorthand (`-24h`, `-7d`). Default window
  `-24h` for analytics, unbounded for the session list.
- **Errors**: RFC 9457 `application/problem+json` — `{type, title, status, detail, instance,
  errors?}`, `type` a stable URN (`urn:argus:error:invalid-cursor`).
- **Filter semantics**: repeated params OR within a field, AND across fields.
- **Null vs zero**: a counter that is *not attributable* under the active filter is `null`, never
  `0` (§4.3 on model filters). A zero means "measured zero". Any agent-supplied vocabulary is
  passed through verbatim, including values Argus has never seen.
- **`ETag`/`If-None-Match`** on session detail and analytics (hash of the underlying `max(ts,seq)` +
  filter).

### 4.4 OpenAPI-first and the TS client

- `server/api/openapi.yaml` is written first for every endpoint; a handler PR that changes a shape
  without the spec fails CI.
- Server side: **no server codegen.** Hand-written chi handlers; conformance enforced by
  `httpapi/conformance_test.go`, which loads the spec with `kin-openapi`, runs the real router over
  the fake store, and validates routing + every response body against the schema for a table of ~50
  requests, with a meta-assertion that the table covers 100 % of `operationId`s.
- Client side: `pnpm gen:api` runs `openapi-typescript@7.13.0` → `web/src/api/schema.d.ts`; a thin
  `web/src/api/client.ts` wraps `openapi-fetch@0.17.0`. The generated file is committed; CI
  regenerates and `git diff --exit-code`s it.
- SSE payload schemas live in the same file as `components.schemas.StreamEvent` (SSE documented as a
  `text/event-stream` response) so the frontend gets types for stream frames too.
- Free-form vocabularies are typed as `string`, never as a TS union — a generated union would make
  an unseen `query_source` a type error in the UI.

## 5. SSE design

Two channels, one hub.

| Channel | Route | Contents |
|---|---|---|
| session | `GET /api/v1/sessions/{id}/stream` | events of that session + its projection updates |
| firehose | `GET /api/v1/stream?kinds=&project=&vendor=` | all events (filtered), plus `session` frames |

### 5.1 Framing

```
id: MTc2ODk…
event: event
data: {"event_ref":"MTc2ODk…","seq":918234,"ts":"…","session_id":"3f7a…","kind":"tool.result", …}

event: session
data: {"id":"3f7a…","status":"active","turn_count":12,"cost":{…}}

event: stats
data: {"events_per_sec":42.1,"active_sessions":3,"queue_depth":0,"ingest_lag_ms":180,"dropped_total":0}

: heartbeat
```

- `event: event` — a persisted event, **slim shape** (no `attrs`; the UI fetches the full event by
  `event_ref` when the user opens the drawer).
- `event: session` — debounced (500 ms per session) projection snapshot. **No `id:` line**: the
  browser latches `Last-Event-ID` from *any* `id:`, so an `id:` on a non-replayable frame would
  corrupt replay.
- `event: stats` — every 2 s, pipeline health; makes dropped events visible. No `id:`.
- `event: lag` — `{"dropped": N}` when a subscriber's buffer overflowed (the client refetches rather
  than trusting local state). No `id:`.
- `event: reset` — `{"reason":"replay_window_exceeded","from":"…"}`. No `id:`.
- `event: shutdown` — on graceful shutdown, so the browser reconnects instead of erroring.
- `: heartbeat` comment every `ARGUS_STREAM_HEARTBEAT` (15 s); `retry: 3000` once at open.
- **`id:` appears only on `event: event` frames**, valued as the event's `event_ref` (`ts`+`seq`),
  because replay must be bounded by `ts` to stay indexed (§5.2).

### 5.2 Reconnect / Last-Event-ID

On `Last-Event-ID: <event_ref>` (or `?after=<event_ref>`), the handler decodes the ref to
`(ts, seq)` and calls `store.EventsSince(after, windowStart = max(ts, now −
ARGUS_STREAM_REPLAY_WINDOW), limit = ARGUS_STREAM_REPLAY_MAX)`. The SQL predicate is
`ts >= $windowStart AND (ts, seq) > ($ts, $seq) ORDER BY ts, seq LIMIT $n`, which rides the
`(ts, seq)` primary key and prunes to at most two partitions — as opposed to a bare `seq > $n`,
which has no usable index and would scan 90 days of partitions on every reconnect.

If the requested position predates the window, the handler sends `event: reset` first and the client
drops local state and refetches via REST. Correctness rule: **attach to the hub before running the
DB replay query**, buffering live events meanwhile, then dedupe by `event_ref` on flush — otherwise
events landing between query and attach are lost.

### 5.3 Hub

```go
type Hub struct { /* mu, map[subID]*sub, topics */ }

// Envelope carries the fields the hub filters on that model.Event does not have.
// project comes from the session projection row the publisher just wrote.
type Envelope struct { Event model.Event; Project string }

func (h *Hub) Subscribe(topic Topic, filter Filter) (*Subscription, error)
func (h *Hub) Publish(evs []Envelope, sess []model.SessionSummary)
```

- In-process, no Redis (single-binary constraint). `Publish` is called by the ingest workers
  **after** the write transaction commits, with only the events that were actually persisted — so a
  dedup-suppressed event never appears twice in a browser, and an event the UI shows is always an
  event that is stored.
- `?project=` on the firehose is served by `Envelope.Project`, filled by the publisher from the
  session row it just upserted. Events for a session whose project is still unknown carry `""` and
  match no project filter — documented, and self-correcting once the `SessionStart` hook lands.
- Topics: `Topic{Kind: All}` and `Topic{Kind: Session, ID: id}`; a map keyed by session id keeps
  fan-out O(subscribers-of-that-session).
- Per-subscriber buffered channel (`ARGUS_STREAM_BUFFER`, 256). Full → drop oldest, increment the
  subscriber's `dropped` counter, schedule a `lag` frame. **Publish never blocks** — a stalled
  browser must not be able to slow ingestion. The single most important property of the hub; it gets
  a dedicated test.
- `ARGUS_STREAM_MAX_SUBSCRIBERS` (default 100) → 503 beyond it.
- Writer goroutine per connection: `select` on subscription chan / heartbeat ticker /
  `r.Context().Done()`; `http.NewResponseController(w).Flush()` after each frame. Headers:
  `Content-Type: text/event-stream`, `Cache-Control: no-store`, `X-Accel-Buffering: no`,
  `Connection: keep-alive`.
- Sim and tests use the same hub, so `argusd sim` visibly drives the live view end to end.

## 7. argus-sim

`argusd sim` / `argus-sim` — a client that speaks the **real wire protocols to a real server**
(`--target http://localhost:8080`). It never touches the database, never imports `store`. That
constraint makes it a genuine end-to-end exercise of the ingestion path, and it means
`docker compose up && argus-sim` is the demo.

**Fidelity rule (normative).** The simulator may only emit attributes that the live capture or the
research doc records the real agent emitting, on the events that carry them. Specifically it **must
not** emit `agent_id`/`parent_agent_id` on `api_request`/`tool_result` OTel events (§1.9), and it
**must** emit the unprefixed `event.name` form alongside the prefixed `body` exactly as the capture
shows (§1.5.1). Any attribute the sim emits carries a code comment citing its source line in
`docs/research/live-capture-2026-08-11.md` or `telemetry-surfaces.md`. A simulator that invents an
attribute makes an unimplementable feature look green in every test and demo; the failure then
surfaces only when the owner points real Claude Code at it.

### 7.1 Generated traffic

Per virtual session:

1. `SessionStart` hook (`start_type` fresh 0.7 / resume 0.2 / continue 0.1) + a
   `claude_code.session.count` metric point. Resource attributes mirror the capture
   (`service.name=claude-code`, `service.version`, `os.type`, `host.arch`), and `terminal.type` is
   drawn from a set that **includes undocumented values** (`wsl-Ubuntu`, `vscode`, `iTerm.app`,
   `some-new-terminal`).
2. 1–20 turns (geometric, mean 6). Per turn:
   - `UserPromptSubmit` hook **and** a `user_prompt` log event with the same `prompt_id` (this is
     what exercises cross-source merge), the log event carrying `prompt_length` + `message.uuid`.
   - 1–8 `api_request` events carrying `query_source` drawn from a distribution that mixes
     live-observed values, documented-but-unobserved values, and an invented one:
     `sdk` 0.45, `""`(absent) 0.25, `main` 0.10, `subagent` 0.08, `generate_session_title` 0.07,
     `auxiliary` 0.03, `a_future_query_source` 0.02 — and **no `agent_id`**. 5 in 6 carry
     `prompt.id`; the `generate_session_title` ones deliberately omit it, exercising the
     out-of-turn path (§1.1). Tokens: lognormal — input μ=ln(1500) σ=0.8, output μ=ln(600) σ=1.0,
     `cache_read` 0 or lognormal μ=ln(40000) σ=1.2 (p=0.75), `cache_creation` lognormal
     μ=ln(3000) σ=1.0 (p=0.3). `duration_ms` lognormal μ=ln(4000) σ=0.7. `cost_usd_micros` from a
     built-in price table so reported cost is self-consistent; `--cost-mode=omit` drops it to
     exercise the estimated-cost path.
   - 0–12 tool calls. Mix: Read 0.28, Edit 0.18, Bash 0.16, Grep 0.10, Write 0.08, Glob 0.06,
     Task 0.05, WebFetch 0.04, `mcp__*` 0.05. Each: `PreToolUse` hook → `tool_decision`
     (**with `tool_use_id`**, per the live capture; accept 0.88 / reject 0.12; `source` config 0.55,
     hook 0.05, user_permanent 0.15, user_temporary 0.15, user_reject 0.08, user_abort 0.02, plus a
     2 % draw of an invented source value) → if accepted, `tool_result` (+ `PostToolUse` hook,
     `success` 0.93) with `duration_ms`, `tool_input_size_bytes`, `tool_result_size_bytes`, `error`
     *and* `error_type` on failures, and — when `--tool-details=1` (default, matching the
     quickstart) — `tool_parameters.file_path` / `subagent_type`.
   - `--tool-use-id-in-hooks=true|false` (default **false**, the unverified case) toggles whether
     *hook* payloads carry `tool_use_id`, exercising both `heuristic` and `hook_only`.
     `--tool-use-id-in-decision` defaults to **true** (live-capture-verified) and remains
     switchable so the degraded path stays testable.
   - `Task`/`Agent` calls (p=0.05 per tool call, max depth 2) emit `SubagentStart`, a nested
     mini-session whose `api_request`s carry `query_source` (no `agent_id`) and whose **hook**
     payloads carry `agent_id`/`parent_agent_id`, then `SubagentStop`.
   - occasional `PermissionRequest` before a `user_*` decision, with a human-latency gap (lognormal
     μ=ln(3000) σ=1.1) so `wait_ms` is realistic.
   - `Stop` hook + `assistant_response`.
   - `hook_registered` events at session start and a `hook_execution_start`/`_complete` pair around
     every hook batch, with `total_duration_ms` drawn lognormal μ=ln(8) σ=0.9 — so the hook-latency
     panel has data and Argus's own overhead is visible in the demo.
   - p=0.03 `api_error`, p=0.01 `api_refusal`, p=0.02 `permission_mode_changed`, p=0.05
     `FileChanged` burst, p=0.02 `PreCompact`/`PostCompact` pair.
3. `SessionEnd` hook (p=0.85 — 15 % of sessions are abandoned with no end event, because that is
   real, and the sweep logic must be exercised).
4. Every 60 s of simulated time: an OTLP metrics export with `cost.usage`, `token.usage`,
   `lines_of_code.count`, `active_time.total`, `code_edit_tool.decision`, and occasionally
   `commit.count` / `pull_request.count`.

Projects from a fixed set (`argus`, `platform`, `micro-services/studio`, `dotfiles`, `legacy-app`),
models from `claude-opus-5`, `claude-sonnet-4-5`, `claude-haiku-4-5` weighted 0.2/0.65/0.15.
`legacy-app` is metrics-only (no log events) so the "logs exporter appears off" banner has a demo
case.

Chaos flags, because these paths need a repro: `--chaos-duplicates` (resend 3 % → dedup ledger),
`--chaos-out-of-order` (hold 5 % for 5–60 s → late rollups via `rollup_dirty`), `--chaos-orphans`
(turn events before `SessionStart` → stub-on-reference **and** the late-project rollup re-mark),
`--chaos-clock-skew` (2 % ±1 h, plus an opt-in beyond-retention event to exercise `too_old`),
`--chaos-unknown` (invented `event.name` → `kind='unknown'`).

### 7.2 Wire output, determinism, rate control

- Transport: OTLP/HTTP protobuf by default (`--otlp-protocol=http/protobuf|http/json`) to
  `POST {target}/v1/logs` and `/v1/metrics`, built with the same `go.opentelemetry.io/proto/otlp`
  types the receiver decodes; hooks as `POST {target}/ingest/hook`. Batching mirrors Claude Code's
  defaults (logs 5 s, metrics 60 s) unless `--flush-immediately`. `--out=dir/` writes the same
  payloads to files instead of POSTing (fixture generation — the Go and Vue suites both consume
  sim-produced fixtures, so fixtures cannot drift from the normalizer's expectations).
- `event.sequence` is emitted **zero-based, dense, per session, shared across all event kinds**,
  exactly as the capture shows — the property the dedup key and the timeline tiebreak rely on.
- **Determinism**: `--seed=N` (default 1) drives one `math/rand/v2.PCG`; per-session generators are
  derived by `rand.NewPCG(seed, sessionOrdinal)` so a session's content is independent of
  concurrency. **`--clock-origin=<RFC3339>` anchors every timestamp**, defaulting to the fixed epoch
  `2026-01-01T00:00:00Z` whenever `--out` is used or `--deterministic` is passed, and to
  `now − backfill` otherwise. Without a fixed origin, "identical seed ⇒ byte-identical payloads" is
  false (timestamps move with the wall clock) and a second seeded run would produce fresh dedup keys
  instead of being suppressed. Identical `seed` + `clock-origin` + flags ⇒ byte-identical payload
  sequence, asserted by a golden test over `--out`; a second run against a live server inserts zero
  rows.
- Modes: `--mode=demo` (default `--sessions=25 --speed=200 --backfill=14d`, historical timestamps so
  analytics has shape) and `--mode=load` (`--rate=<events/s> --concurrency=N --duration=…`, live
  timestamps, for backpressure testing). `--speed=X` compresses simulated time, so a 14-day backfill
  lands in seconds.
- Exit report: sessions/events/hooks/metric points sent, HTTP status histogram, throughput, and
  non-2xx bodies — so a 429/503 storm during load testing is legible.

## 8. Deploy & CI

### 8.1 Dockerfile (`server/Dockerfile`, context = repo root)

```
FROM node:25-alpine AS web
  corepack enable; pnpm install --frozen-lockfile; pnpm build   → /web/dist

FROM golang:1.25-alpine AS build
  go mod download (cached layer)
  COPY --from=web /web/dist server/internal/httpapi/assets/dist
  CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X …/internal/telemetry.Version=$VERSION \
      -X …/internal/telemetry.Commit=$COMMIT" ./cmd/argusd

FROM gcr.io/distroless/static-debian12:nonroot
  COPY --from=build /out/argusd /argusd
  USER nonroot:nonroot
  EXPOSE 8080
  ENTRYPOINT ["/argusd", "serve"]
```

Distroless (not alpine): the binary is static, nothing needs a shell, the smaller attack surface is
free. Trade-off accepted: no `docker exec sh` — debugging uses `/healthz`, `/metrics`, logs, and a
`:debug` tag from `distroless/static:debug`. Web assets are embedded rather than served by nginx:
one container, one port, no CORS, no reverse-proxy config in the quickstart.

## 9. Non-goals and open questions

### 9.1 Non-goals in v1

From DECISIONS.md: alerting; fleet view; auth (seam only); retention UI; git-join ($/merged-MR);
JSONL transcript enrichment; OTel traces ingestion (accepted-and-discarded at `/v1/traces`);
ClickHouse backend; multi-tenancy; SaaS.

Added by this spec, same reasoning:
- **No OTLP/gRPC receiver.** HTTP only.
- **No per-subagent cost or token numbers, and no semantic interpretation of `query_source`**
  (§1.9) — the telemetry does not support the first and the vocabulary is undocumented for the
  second. The raw `by_query_source` map is what v1 reports.
- **No prompt/response content UI.** Content is stored in `attrs` if the user opts in and is visible
  in the raw-event drawer, but there is no rendered conversation view.
- **No write path from the UI.** Read-only apart from ingest. No annotations, tagging, or deletes.
- **No disk spool for ingest** (§3.6), **no GIN index on `attrs`**, **no index on `events.id`**
  (§2.2), **no async projector** (§1.6), **no server-side timeline collapsing** (§1.5.3), **no
  `DEFAULT` partition** (§2.2), **no `query_source` dimension in rollups** (§2.4) — each rejected
  with its reason above.
- **No Analytics API / Compliance API polling.**
- **No cross-agent adapters beyond the `vendor` field and the `unknown` fallback.**
